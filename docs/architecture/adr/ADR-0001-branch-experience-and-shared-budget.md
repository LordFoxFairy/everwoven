# ADR-0001 · 通过新经历分叉，共享不可变前缀与预算总上限

日期：2026-09-10。状态：设计评审通过，可作为阶段实施基线；未实施。范围：分支存档、后续M2/M3数据建模。

评审依据：[技术方案1.2审查](../DESIGN-REVIEW-1.2-2026-09-10.md)。设计通过不替代迁移、真实并发与Provider验收。

## 背景

用户希望回到上一幕重新选择并保留原路线。既有Experience固定开局版本、节点一次消费，预算与任务可恢复。直接把进度倒回会破坏已消费节点、记忆、费用和在途任务归属。

## 方案比较

1. **覆盖同一经历的后续记录**：简单但破坏历史/任务/引用，排除。
2. **一个Experience塞多分支和独立Branch聚合**：要重定义几乎所有现有节点/预算/恢复作用域，当前收益不足。
3. **新Experience fork＋不可变Savepoint/Snapshot共享前缀**：沿用现有独立经历边界，选择此方案。

## 决策

- branch不是第二份可变世界真值；同根多Experience投影为故事树。
- 只有已确认的稳定决策存档点作为首版来源。child生成自己的fork_base/decision/空稿，复用过去的确认快照，不伪造播放证据。
- 旧事实/媒体不可改，前缀访问通过显式持久引用，GC理解所有分支。
- 根树共享BudgetScope；Experience子限额约束本分支新增消费。同一账本按scope与experience汇总，不复制资金/许可/费用。
- 默认复制来源固定配置，不把分支当成偷偷换供应商或重试未知任务的入口。

## 代价与约束

增加fork_base证据模式、来源查询、引用保留和scope级预算闸门；收益是隔离清楚，旧节点不用重新消费。树查询需要去重和分页，但不要求复制整棵媒体树。预算scope基础应在首个真实账本前落地；完整分支UI可以后置。

无物理外键，关联检查仍由短事务WriteGate负责。新迁移不得改写已应用M0历史迁移。详细字段、时序和测试门槛见[专项设计](../BRANCH-SAVEPOINTS-DESIGN.md)。
