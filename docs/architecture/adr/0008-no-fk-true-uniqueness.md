# ADR-0008：无外键与真实业务唯一

状态：Accepted（用户明确指定的设计约定；正式仓库实现待验收）。2026-09-10。

## 背景

用户要求禁止物理外键，并澄清真实业务唯一可以保留，担心的是伪唯一。V1.1复合FK和跨表触发器样本因此不再作为实施基线。

## 决策

Prisma/SQLite保留标量关联ID，不声明@relation、不创建FK/级联或引用模拟触发器。WriteGate用例统一校验存在、同owner/experience及删除生命周期；SQLite先写取得写权再查关联，避免事务外先查后写。

主键与经过登记的真实业务唯一保留，不设数量上限。删除冗余owner+id；角色名、标题、hash等不唯一。当前M0有15主键与13项业务唯一，详见 [唯一登记表](../UNIQUE-KEY-REGISTER.md)。

## 后果

正面：关系生命周期更显式；避免误把同名/同图设计为冲突；不为了ORM导航建立冗余唯一。

代价：数据库不会阻止悬空/跨域引用或非法删除。所有写入口、导入/GC/维护必须遵守应用协议，增加用例测试和一致性扫描。禁止绕过服务直接改业务库。SQLite写门不自动移植到多实例PostgreSQL，迁库须重做锁范围与事务评审。

普通删除使用deletedAt并保留历史引用；文件GC先在事务内置deleting阻断新引用，再在事务外回收。归档、删除、撤销与冻结版本不是同一动作。

## 验收

Schema及生成SQL零外键、真实唯一逐条登记；数据库接受孤立ID是预期边界，用例必须拦截；并发创建、CAS、删除/引用竞争等通过协议与实际Prisma测试后才算实现完成。
