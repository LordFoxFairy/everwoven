# ADR-0007：分段任务与单一编排，保持未来实时传输独立

## 状态

Proposed · 2026-09-10。一期分段交互已在 PRD 确定，本文约束正式实现；替代早期文档中一期默认原生实时会话的假设。

## 背景

当前认可体验是“生成 → 播放 → 结束后回应”。已有 LiveVideoProvider 是媒体流会话，官方任务适配是有限任务，二者生命周期不等价。团队熟悉 LangChain，同时希望使用 Vercel AI SDK 交互能力。

## 决策

LangChain/LangGraph 是唯一线上编排路径；AI SDK 只承担交互适配/流封装。runtime 持有任务、费用与恢复记录；Player 显示快照/媒体/当前节点，不持有供应商密钥或任务真值。

ProviderBinding 固定供应商、精确模型、适配/能力版本；job 与 realtime 使用不同 port。模型提案、生成片段、播放证据和确认事实分层。当前用户只在片段结束后的有效节点提交行动，不用实时聊天框伪装未实现的介入能力。

## 后果

### 正面
- 换供应商不改玩家交互语义；新增原生实时模型时不破坏已有任务存档。
- 线上只有一条编排链，预算、追踪与恢复集中。
- 费用、播放和故事真值不互相冒充，失败可解释。

### 代价
- 必须维护清楚的 DTO、状态与 adapter 测试，不存在安装 SDK 即无缝。
- 真实实时传输将来仍需单独处理媒体、打断和费用准入；不是打开布尔开关。
- 语义校验和角色一致性需模型实测，类型系统不能证明剧情质量。

## 比较过的方案

- 简单请求 AI SDK Agent、复杂请求 LangGraph：重复执行/预算/恢复体系，不采用。
- 所有视频都抽象成 send/close：掩盖任务不可即时介入与取消的限制，不采用。
- 所有输出先写世界事实：把计划当已呈现后果，违反玩家参与与恢复契约。
