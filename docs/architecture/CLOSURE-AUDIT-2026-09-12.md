## 3. 设计模式的使用标准

沿用模块化单体。短期“页面里直接拼SDK请求”会掩盖任务和计费缺口；现在拆微服务则增加部署与一致性成本。两者均不作为推荐路线。

| 模式/思想 | 实际落点 | 必须带来的收益与约束 |
|---|---|---|
| 端口与适配器、依赖注入 | 模型、素材、凭证、时钟、ID与事务存储；宿主负责组合 | 替换供应商不改玩家页面；注入用普通构造参数/工厂，不上通用DI容器 |
| 策略＋显式注册表 | supplier → connection → model → frozen binding | 能力不支持就拦截；不自动切fal，不以“兼容接口”推断所有模型能力一致 |
| 应用用例＋事务边界 | 创建/修改/删除/恢复、提交回应、完成播放、fork | Router只做输入、身份、调用与错误映射；幂等回执和业务变化原子提交 |
| 有限状态机 | 供应商操作、回合、播放各自建模 | completed生成不等于played；未播放完成不显示可提交节点；迟到结果不能推进新回合 |
| Outbox＋租约＋对账 | 提交持久任务后由内部worker执行 | 进程重启可恢复；发送后失去回执进入未知，不因超时重新POST付费任务 |
| 不可变版本/快照 | 固定剧本人物绑定，稳定Savepoint及新Experience | 原路不覆盖；从B分叉不读原路后续C/D；共享媒体不复制任务和费用 |
| 查询投影 | 故事树、舞台view model、任务摘要 | UI只读可展示状态，不能自行推导任务成功或事实成立；不引入独立CQRS服务 |

不新增万能BaseRepository、所有实体继承的BaseService、完整事件溯源框架、消息中间件、开放动态插件或每轮多Agent。现有库可以完成的UI、表单校验、请求缓存和传输继续复用，业务事务保证不交给框架名称代替。

## 4. 下一切片建议：M0-C，本机正式持久化入口

目标：一套页面通过受保护tRPC调用既有剧本用例，保存真实SQLite数据，重启能读回。先接草稿根对象，不假装人物/素材绑定一起完成。

1. 启动生命周期：显式数据目录、批准迁移、稳定本机身份、服务实例所有权。开发热更新不重复启动后台调度。
2. 会话边界：本机初始化及会话、服务器解析owner、请求来源与CSRF防护；浏览器不传可信ownerId。凭据不得进入前端bundle、URL持久记录或日志。
3. 用例边界：复用现有CRUD/CAS/回执测试，将Prisma事务细节收敛到具体事务适配；避免拆成多个各自提交的仓库调用。
4. 契约边界：AppRouter＋运行时schema唯一正式输入输出来源；列出业务错误、可重试条件、commandId和expectedRevision。旧REST列表只保留历史追踪。
5. 前端边界：同一创作UI经正式数据适配调用；Mock继续在前端，无后端假Provider。未映射的人物/素材字段明确保留或阻断导入，不静默丢弃。
6. 数据保护：导入前预览与备份、来源ID映射、幂等导入、用户明确确认。首次不自动导入演练历史，不把UUIDv4旧内容直接冒充正式UUIDv7对象。
7. 交付边界：代码、API、迁移说明、架构/时序和可执行验收同步；M0-C可先用本机Next验证，正式Docker持久化在其生命周期测试通过后更新。

本机单用户不是公网多人认证。APP_ENV只选运行模式，不作为权限或生产就绪证明；当前端口与界面不增加第二套。

### 必须通过的验收

- 空数据目录首次显式初始化；随后重启保持同一身份和数据。
- 未初始化、无会话、错误来源和跨owner请求不会读写用户内容。
- create/update/delete/restore真实落库；重启、刷新与软删除恢复结果正确。
- 同commandId相同内容重放，换内容冲突；两个窗口用旧revision写入只成功一次。
- 写入失败不显示保存成功；SQLite忙、磁盘写失败、回执失败均不产生半成功。
- 备份包含一致的DB状态；涉及素材时采用带清单的一致性协议，不热拷贝WAL主文件冒充完整备份。
- 旧浏览器数据保持不动；显式导入失败可重试，演练数据与正式数据隔离。

## 5. 后续交付顺序与真正完成标准

1. **M0-C：正式存取。** 先解决生命周期/身份/持久化最小垂直链路。
2. **M1：人物、图片与开局版本。** 图片验证和安全存储、关联检查、删除保护、剧本/人物版本固定。
3. **M2：真实生成任务。** 官方供应商精确能力重新核验；固定binding、任务提交/查询、预算与未知结果恢复。真实付费验收另确认凭据和预算。
4. **M3：两轮真实游玩与恢复。** 视频下载检查 → 播放 → 情境建议/自由回应 → 下一段；恢复后不重复提交、不漏账、不把提案当事实。
5. **B1：从稳定节点分支。** 使用已设计的不可变Savepoint与来源链；原路线、媒体引用、预算归属都保持正确。完整树UI按原阶段范围，不提前扩大一期。

最终验收是一条实际用户路径：创建剧本/人物/图 → 固定开局 → 真实生成 → 播完显示可行动建议与自由回应 → 第二段兑现回应 → 保存并重启恢复 → 从合格历史节点另开路线且原路不受影响。B1未交付前单独标记待实现，不以有树形页面宣称通过。

每个切片独立报告：实现了什么、接口/数据变了什么、跑了哪些真实验证、剩余限制、回滚方式。架构图的实线代表已实现，规划用虚线；没有测试证据就不升级状态。
