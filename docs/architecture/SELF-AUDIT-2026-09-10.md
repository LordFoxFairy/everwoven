# V1 技术方案自审 · 聚焦闭环与Provider

2026-09-10 · 审核对象：技术/数据/API设计、Prisma审核DDL、现有MiniMax请求与任务适配器及测试；结合本次官方V2资料核对。不是形式审查或“通过测试=产品完成”。

## 1. 总结

**方向成立；修订后可进入M0；正式Provider收费与真实游玩闭环尚待实现、实测。** 上一版“文档字段合法”只证明一个层面，这次确实找到业务缺口。

| 判断面 | 裁决 |
|---|---|
| 分层与维护 | 保留模块化单体、runtime唯一数据拥有者、纯领域与基础设施分离；不提前上微服务 |
| 数据规范 | 用户指定零外键、真实唯一策略已落实到审核SQL；这是项目规范，不宣称所有大厂统一如此 |
| API规范 | 幂等/条件请求/错误/SSE/媒体分离方向正确；本次补回合恢复目标、预算存储和明确Connection |
| Provider通用性 | 原submit/query草图不够；专项规范已补身份、能力、请求、计量、核对边界；生产代码整改尚未执行 |
| 产品闭环 | 设计链路可追溯，但没有真实两轮媒体/事实/恢复证据，不称可玩闭环已完成 |

## 2. 具体问题、修订与剩余验证

### P1 · Provider只固定视频模型，未固定整条收费执行链

架构说文本/视频分别绑定，原API只选一个视频binding，实际代码没有规划/检查profile。改默认LLM可能让已确认报价漂移。

**修订：** 服务端ExecutionProfileVersion固定规划/视频/检查绑定、graph/prompt/schema和预算；Quote暴露其ID。Quote前批准范围，规划后PreparedGeneration固化实际请求并检查未越界。超范围先停再确认。剩余：M2持久结构、限次/限额和故障注入。

### P1 · 缺少地区/账户身份，以及场景级能力准入

现有minimax-jobs主机固定CN；旧binding没有明确Connection选择。API中的imageInput布尔摘要表达不了“首帧可用但人物参考不可用”。官方V2文档区分H3和Max场景，也明确I2V比例由输入决定。

**修订：** connectionId/region进入公开目录与绑定；宿主固定endpoint/account/credential。Capability按场景/角色/规格核验；Quote可返回provider_resolved像素，避免猜分辨率。参考图不受支持就不发送，不偷偷改用另一供应商或额外图像生成。剩余：真正连接注入、输入传输、角色连续性与音频验证。

### P1 · 费用观察和超期核对不足

既有适配器仅保留两种seconds，正式H3输入/输出不总能用一个秒数结算；官方查询/列表有最近7天范围，旧方案没有明确超期停止条件。

**修订：** 完整meter+价格版本+证据；queryUntil与retentionExpired关注码；过期不释放预留、不凭404重提、不无限轮询。人工核对是内部受控用例，未实现前保持阻断。剩余：M2真实账单/失败/取消/更正验证，关键端点仅Mock不是收费验收。

上述资料与推论分开记录于[Provider规范§4/6](PROVIDER-DESIGN.md)。

### P2 · 终态失败回合在重开后失去可发现的重试目标

快照只有pendingOperationIds，已结清失败操作不在其中；旧窗口202不应是重开存档的依赖。

**修订：** recoveryTarget保留turnId、operationId、允许重试模式/核对要求，即使外部操作终态仍可定位。机器契约及正反样本同步。剩余：M2关闭窗口/重启/查询快照到重试的HTTP测试。

### P2 · 创建时接受预算，但M1未定义保存位置

零支出不能代替玩家设置的非零limit。

**修订：** Experience两个必填字段budgetLimitMicros/budgetCurrency；审核Prisma/SQL同步，不设任意默认值。增加另开连接验证保存原值的样本。M2沿用limit真值，预算账本另建。剩余：真实Prisma创建/升级测试。

## 3. 按真实主链路验收，而非按按钮验收

| 场景 | 应满足的闭环 | 实施Gate |
|---|---|---|
| 设定→角色→图片→冻结开局 | 保存真值、不可变版本、图片用途一致、零模型调用 | M1 |
| 开始→报价→受理 | 清楚展示模型/素材/声音/上限，重复提交一次接受 | M2 |
| 规划→请求→生成 | 固定执行profile、输入能力准入、预算内有界执行 | M2 |
| 成功→本地媒体→播放 | URL失效不丢已落地存档，检查后才可播放 | M2/M3 |
| 看完→建议/自由回应→下一段 | 节点身份可消费一次，建议失败仍有引导自由回应 | M3 |
| 事实/角色记忆→下段后果 | 已确认视频证据驱动，不将计划提前写成发生过 | M3质量Gate |
| 暂停/断网/双窗口/重开 | 草稿、播放、回合、控制、预算分别可恢复 | M0–M3 |
| 超期未知费用/供应商停用 | 保留责任，受控核对，不自动重提或虚称退款 | M2 |

尤其**用户体验连续**不等于**模型原生实时打断**。一期有限片段方案不退回AI Chat，也不把任务等待包装成实时视频流。

## 4. 规范通过的依据与边界

- ID/时间/金额/生命周期/索引有明确规则；PK与真实唯一保留，非法跨owner引用交由事务用例阻断。直接SQL可破坏引用的风险明确接受，不宣称无FK自动安全。
- 幂等回执和业务写入同事务；版本分工、会话/CSRF、媒体授权、快照与事件世代已定义；OpenAPI校验不证明这些语义已实现。
- 当前47操作是分期合同，不要求M0一次写完；不因未来扩展创建空服务。新schema/SDK/迁移升级需统一契约测试与精确版本记录。
- Provider抽象按真实变化划分：供应商/连接/模型/任务/素材/计量；不堆砌过度通用参数。新增model先登记能力和证据，再开准入。

## 5. 本轮验证与结论

本轮主会话实际验证：OpenAPI3.1.1通过；51项正反样本、1483次引用/结构断言通过；24项临时SQLite结构/协议样本通过；Prisma7.10 validate与DDL重新生成通过；现有14文件137测试、typecheck/build通过。API仍为36路径/47操作，87schemas，所有x-implemented=false。

Helmholtz独立只读复核确认恢复目标、预算持久化两项设计缺口可关闭；快速复核Provider专项后，限定范围未发现直接阻断流程的自相矛盾。此结论不是生产实现/外部API/音画质量验收。生产代码未改、没有迁移用户库、没有付费模型调用。独立只读复核发现的2项数据/API缺口由主会话修改；Provider专项由主会话对照代码与官方资料审核。

**下一步不是继续无边界扩写PRD，而是按已修订基线执行M0，并建立M2 Provider契约/故障测试清单。** 以真实落地逐个关闭风险，而非保证设计永远没有问题。
