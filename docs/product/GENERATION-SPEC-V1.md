# V1 内容生成、角色与视频质量规格

配套[PRD1.9](../../FINAL-PRD.md)，2026-09-10。借鉴附件将基础设定/片段/生成规则拆开的形式，**不采用附件中的固定恋爱阶段、必然关系升级或两项固定分支**。本文定义产品语义与质量；不是直接可执行的system prompt或已经部署的内部schema。

## 1. 对象和字段：谁提供、谁确认、何时生效

| 层/产品字段 | 含义与来源 | 用户可见 | 生效与约束 |
|---|---|---|---|
| 起点：名称/世界/主要角色 | 用户原文/模板/经采纳的AI草案 | 是 | 固定版本后用于开局；不会被每轮自动覆盖 |
| 初始关系/玩家身份 | 用户确认的开局设定 | 是 | 只属当前经历；不默认玩家已经喜欢/同意某事 |
| 角色稳定设定 | 性格、语言、动机、兴趣、边界 | 基础部分 | 模板版本固定；不是跨局共享记忆 |
| turnId / segmentId / previousSegmentId | 本次回应、媒体片段及来源 | 内部，回顾可用序号展示 | UUID等内部身份由runtime生成，不能用S02展示编号充当PK |
| 本轮玩家行动 | 当前节点的建议选择或自由表达 | 是 | 明确提交后成为Intent，草稿不算 |
| 候选情境 | 地点/人物可见状态/计划动作 | 生成检查前不展示成事实 | 规划输出，不直接写共同记忆 |
| 角色台词候选 | 本轮计划说的话 | 实际呈现或明确文本模式才展示 | 非真实音频转录，不能直接当精准字幕 |
| 互动焦点 | 让玩家现在值得回应的变化/问题 | 通过片段体验 | 不是强迫选项或必须点击的任务 |
| 建议候选 | 几种合理而不同的当下回应 | 片段后且节点有效才显示 | 不含结果剧透、不预绑定固定剧情结局 |
| 候选后果 | 提案预计发生的行为/关系变化 | 不提前展示成已发生 | 等待媒体/播放/语义证据确认 |
| 确认事实 | 已确认开局设定或被验证的已呈现后果 | 按角色知情/用户已见范围 | 有来源、版本、有效性；回合新事实不能来自计划自证 |
| 当前关系 | 基于已确认互动的描述 | 可从行为看见；非数值面板 | 拒绝/边界要影响后续，不擅定玩家内心 |
| 未解决线索 | 已出现但尚未得到回答的信息 | 已知部分可见 | 不无限堆积新秘密，不固定必须完成的阶段 |
| 角色私有创作约束 | 内部一致性设想、知情边界 | 默认不输出 | 与确认事实分库/分类型；不得混入共同记忆或诊断公开正文 |
| 可恢复摘要 | 场景/节点/行动/草稿/回合/媒体 | 回访展示简短摘要 | 由权威保存点投影，不重新编造剧情 |

产品字段映射现有公开API见[页面字段字典](PAGE-SPEC-V1.md)；内部候选/检查/事实结构在M2/M3随专门schema校验落地。参考文档JSON是内容样例，不作为我们的数据库结构或提示词指令直接执行。

## 2. 五个阶段的职责

| 阶段 | 输入 | 输出 | 执行限制/失败 |
|---|---|---|---|
| A 起点整理 | 原文、已选角色、边界 | 可确认的基础草案 | 手工编辑先可用；外部AI整理另走授权，不暗中收费 |
| B 本轮规划 | 固定起点、确认事实、当前节点、玩家行动、能力/费用包络 | 候选动作/台词/情境/后果/建议 | 结构校验+有限修复；不写事实、不越界替玩家决定 |
| C 视频请求准备 | 已接受规划、实际图像用途/衍生素材、固定执行profile | 持久化有效请求摘要 | 必须落在授权包络；不支持输入组合发出请求数为0 |
| D 生成与检查 | 供应商任务/媒体 | 落地媒体、技术/内容检查证据 | 失败保留原回合；未知受理不重提；不确定不开放自动事实成立 |
| E 播放后归并 | 已验证媒体、有效播放证据、语义判定 | 幂等事实/保存点/新决定节点/空草稿 | 事务一致；下一轮只读确认事实，不读尚未通过的候选 |

```text
已确认起点 + 确认事实 + 用户本轮行动
                  ↓
             有界候选规划
                  ↓
      请求/素材/费用准入 → 生成任务
                  ↓
            媒体落地与检查
                  ↓
        有效播放完成 + 语义可确认
                  ↓
          事实 / 保存点 / 决定节点
                  ↓
           等待用户；不自动续生成
```

候选规划中有新角色、素材、声音方案或费用变化，先停止并重新确认，不把“AI觉得需要”当作授权。播放器ended只是一项证据，前端不得自行合并事实或造选项。

## 3. 叙事与角色质量规则

| 维度 | 合格表现 | 不合格表现 |
|---|---|---|
| 接住行动 | 对实际问题/拒绝/动作给相关反应 | 忽略用户，继续预设表白/事件 |
| 主动但尊重决定 | 人物提出有动机的邀请/行动，同时给拒绝空间 | 替玩家答应、替玩家发言或把沉默当同意 |
| 内容密度 | 一轮有可辨识的新信息、行为或态度 | 多轮只对视/沉默/重复询问，没有后果 |
| 节奏 | 依照用户想深入或想推进来组织 | 强制每段关系升级、固定13阶段/第N段必结局 |
| 建议差异 | 询问、接受、保持边界等不同策略 | 同义句凑数，一项合理一项故意荒谬 |
| 连续性 | 人物身份、服装/场景、已确认约定可追溯 | 每段换脸/换场景或忘记拒绝，无解释漂移 |
| 信息范围 | 人物只依据所知信息行动 | 人物突然知道玩家未表达的心理/内部秘密 |
| 可呈现性 | 动作和台词能在真实时长内表达 | 长篇剧情压成几秒装饰画，字幕讲述画面没发生的事 |

用户可以选择平静相处或暂不推进；互动焦点可以很轻，不为留存制造强制危机。关系题材质量维度不自动变成非恋爱题材的固定故事骨架。

## 4. 视频、图片与声音约束

- 一期一位主要角色、一块视频舞台。参考图数量、模式、时长、输出比例按供应商—地区—模型—版本准入；模型能接三张图不意味着三张图能用于同一种角色。
- 角色外观图、前段尾帧、场景图是不同用途；复用尾帧只能帮助可见状态承接，不能替代叙事记忆。三视图/场景多视图是输入组织策略，不是第一期自动图像生成承诺。
- 长度由动作、实际语音和部署能力共同决定；不全局固定5秒、768P。窗口缩放不是生成请求变更。
- 只有真实音轨才显示音量；明确无声方案必须告知。独立TTS/ASR/音画合成不默认为P0，新增需审核成本和契约。
- 字幕候选不等于真实发音：未验证转录/对齐不得把导演台词当真实字幕。当前无可靠字幕来源时隐藏字幕控件；后续有来源时保存语言/时间轴/校验记录。
- 等待阶段只显示实际进度或简短准备状态，不提前展示本轮“已发生剧情”来填充等待。允许查看旧的已确认摘要，但不混入候选后果。

## 5. 题材示例：说明规则，不成为内置固定剧本

**输入设定：** 用户想与一位认识不久的画师一起整理工作室，关系与行动由用户决定。

**已呈现情境：** 角色递来两张画纸，询问哪张适合挂在窗边。

**合格建议：** “看看两张画的区别”“问问他偏爱哪张”“先聊聊窗外的景色”。用户也可自由说“我不太想选画，想出去走走”。下一段应处理这个意图，角色可提出原因、表达不同意见或一起行动；不直接宣布用户已同意约会或爱上角色。

若视频只显示递画，候选文本里“你答应帮他办画展”未呈现也未经玩家同意，不能进入确认事实。此例只用于回归测试，不为平台规定官方剧情或后续路线。

## 6. 评测记录模板

每条试验记录：caseId、题材标识、输入/拒绝/非选项类别、匿名经历/回合ID、角色/设定版本、执行profile及能力证据版本、Quote、任务/用量、实际媒体、是否完整播放、检查方式（人工/自动）、候选/确认事实差异、相关性/连续性/越权结果、失败原因与修复动作。

隐私：默认脱敏，测试素材使用声明明确；真实提示和图片不写普通日志。模型名/输出视频存在并不能证明来源或质量；错误同样入评测，不只挑成功样例。

标准沿用Gate B的≥30独立样本、接受/拒绝/非选项覆盖；其中至少3例为一种非恋爱情境并分别覆盖三类输入，不强套恋爱关系推进。M2采集基础能力证据，M3完成语义闭环评测；通过后再冻结等待/成本/连续性阈值。人工检查可以用于内部试验但记录耗时；无人值守Alpha须自动检查和故障处理实测，不以prompt自检代替。
