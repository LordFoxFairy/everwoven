# 本地优先的产品形态与独立闭环交付

2026-09-10 · 产品推进说明；已按用户确认的单应用、前端Mock、T3方向修订。

沿用[PRD1.9](../../FINAL-PRD.md)、[页面规格](PAGE-SPEC-V1.md)和[技术实施计划](../superpowers/plans/2026-09-10-local-first-implementation.md)，不改变一期分段交互、模型授权或M4桌面正式验收边界。本稿明确本地与Web的关系、原型去向和下一步用户可见交付，不新增已实现声明。

## 1. 一句话定位

**一个本地优先、由用户设定与回应驱动的生成式互动视频应用；同一产品可在本机浏览器和桌面窗口中使用。**

“本地”描述数据与运行责任，不等于所有模型离线运行；“Web”描述一种界面入口，不自动意味着云端账户、服务器存档或公开社区。

| 形态 | 当前/后续位置 | 数据与运行位置 |
|---|---|---|
| 本机浏览器 | 先承载正式交互开发与验收 | 本机runtime、SQLite、文件素材；浏览器不是真值库 |
| 桌面应用 | 同一产品的目标交付入口；正式验收仍为M4 | 打包宿主启动/停止与凭证存储，复用业务契约和React界面/Player |
| 托管Web | 后续独立部署能力 | 需要托管runtime、身份/存储/预算/同步方案；不只是换域名 |

浏览器与桌面连接同一本机runtime/数据目录时，目标是读取同一份数据；这不等于已实现跨设备同步。桌面与Web共享业务组件和契约，但启动、鉴权、文件选择、窗口操作由宿主适配；不把Next服务端代码直接搬进WebView。

目标交付时用户正常启动不必手动管理数据库或进程。开发阶段仍有开发命令；一键启动、实例互斥、安装/升级流程必须分别实现并测试，当前数据库检查CLI不代表这些已经完成。

## 2. 一套产品，三种使用状态

### 我的空间：回来就知道继续什么

- 已有经历时，以“继续上次经历”为主要入口；新用户显示清楚的创建入口。
- 内容组织为我的剧本、角色与相关图片；提示模板作为起点，不制造虚假社区热度。
- 剧本是可复用的起点，经历是实际玩出来的过程；“继续编辑”与“继续游玩”不混用。
- 供应商、数据目录、备份等放在应用设置，不把首页做成模型控制台。
- 外部使用明亮浅色、清晰排版和人物/素材视觉，不靠霓虹渐变或大量参数展示AI感。

### 创作起点：先表达，再补必要信息

- 先说明想经历什么，再选择/创建人物、按用途添加图片；身份/关系/规则逐步展开。
- 同一编辑模型支持轻创建与详细编辑，不维护两套草稿。
- 手工流程独立成立；AI整理待独立契约与费用就绪再启用，不假装已接通。
- 准备进入时分清经历总预算与单次费用，告知模型、素材去向和真实生成规格。
- 配置改变遵守不可变经历规则：新起点准备新经历，旧经历保留；仅报价过期不新开局。

### 视频现场：界面退后，情境成为主体

- 一块视频占据可用内容区；桌面宽幅适配，完整画面/等比铺满可切换，系统全屏独立。
- 不常驻聊天侧栏、剧本表单或模型控制面板。返回、声音和设置位于可收纳浮层。
- 播放中安静观看；片段有效完成并确认节点后，情境建议与自由回应出现。
- 正常提供2–4项有差异的建议，不固定ABCD；修改建议与直接选择分开，费用授权明确。
- 等待下一段时保留上一有效画面与真实状态，不将循环视频、字幕或假进度冒充实时生成。
- 收起回应、暂停播放、保存离开分别有明确含义；无人回应不自动继续收费生成。

“下一代感”的验收是：容易开始、理解当前情境、自然参与、行动有可见后果、离开还能继续。视觉只是这条体验的承载方式。

## 3. 不以技术层为唯一交付单位

一个独立闭环必须包含：入口→操作→真实结果→保存→重开恢复→失败处理，并有用户可见证据。数据库通过只是其中一层。

| 交付切片 | 用户能完整完成的事 | 不依赖什么 | 验收重点与对应阶段 |
|---|---|---|---|
| S1 本地创作版 | 创建剧本、人物、图片并保存；退出重开继续编辑 | 不依赖模型密钥、付费调用或桌面正式打包 | AC01–14适用本地部分；先M0必要运行/身份/数据保护，再M1正式创作 |
| S2 第一段真实视频 | 从自己的设定确认输入/费用、开始、等待、播放；失败有核对路径 | 不依赖完整广场、订阅、多角色或第二套Provider | M2协议与真实能力证据、M3最小Player接入；一次成功不算完整游玩闭环 |
| S3 两轮参与闭环 | 看完回应→下一段兑现→保存离开→重开继续 | 不依赖物体点击、实时中途打断或跨设备同步 | AC15–34；M3完整Gate B与Web子集，30例质量评测另计 |
| S4 本地桌面Alpha | 正常安装/启动/退出，数据与媒体可恢复，窗口行为自然 | 不依赖用户安装开发环境 | M4限定平台真机、升级/备份/恢复与双端Gate C |

S1内也分小步验收：先剧本保存重开，再人物版本，再图片引用，最后组合起点。每一步都让界面实际消费已完成的服务，避免后端做完一大片但用户一直看到旧演示。

桌面打包技术冒烟可以在不打断主线时提前排查风险；不因此把M4正式验收提前标完成。先云端网站后套壳会偏离当前本地诉求；先把所有桌面分发细节做完再验证互动也会延后核心价值，所以采用共享界面/本机runtime先闭合、桌面再正式交付的顺序。

## 4. 一个应用，前端数据演练

用户已明确否决双应用/双入口，后续只维护现有 `apps/web`。统一以 `pnpm dev` 启动；历史静态设计源只读保留，不继续承接功能。

前端 Mock 数据与行为由 `apps/web/mocks` 管理，复用同一套React组件；不注册成模型Provider、不因密钥配置而自动切换成付费模式。正式数据请求走tRPC，后端只处理真实业务和真实供应商适配。

已有浏览器草稿、角色、图片和演练记录保留原存储，不自动改为Mock种子、不覆盖、不静默迁移到SQLite。历史不同origin的内容必须显式导出/确认后再导入。

当前已提供同一应用内的分段交互演练（无生成视频）；新舞台与正式模型的接入仍待后续切片。演练记录不是真实生成存档，恢复演练不代表恢复视频播放位置。

## 5. 下一步的具体交付

技术栈与后续传输裁决以[T3与前端Mock收敛](../architecture/T3-FRONTEND-MOCK-2026-09-10.md)为准。

当前[M0-A](../implementation/M0-A-2026-09-10.md)已完成数据库切片，尚未完成一键启动、HTTP身份、备份或正式页面接库。

下一次工程目标不是“再加一个基础库”，而是为S1推进必要路径：

1. M0-B明确本机数据目录、单实例与启动/退出边界，保护已有数据。
2. M0-C建立受保护API和客户端校验，再实现M1最小剧本创建/读取/保存；界面接入后演示退出重开。
3. M0-D数据保护与恢复门槛按正式持久内容交付要求完成，不等到用户存了大量内容再补。
4. 逐步补人物与图片，组合成不依赖模型的本地创作闭环；并按页面规格推进核心原型评审。

每次交付说明：用户现在能做什么、入口在哪、什么仍是模拟、重开/失败是否验证、下一处阻断是什么。不再以新增表数、按钮数或单元测试总数代替产品完成度。
