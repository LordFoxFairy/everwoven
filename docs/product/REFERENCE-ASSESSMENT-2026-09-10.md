## 3. 不照搬与原因

| 参考内容 | 本项目处理 | 原因 |
|---|---|---|
| 日本成年女性特定年龄段、英日首发 | 作为他项目定位，不写为我们的已验证用户结论 | 用户已明确人物关系题材优先，但未批准该市场与语言范围 |
| 固定预设恋爱剧情、两轮预制新手视频、A/B和固定关系阶段 | 提示模板可编辑；片段后动态建议+自由回应 | 我们是用户驱动平台，不是固定剧情路线游戏 |
| 每段必须升级关系、最终指定结局 | 依据用户行动推进，允许拒绝与平静相处 | 参与感来自因果与自主性，不是强制亲密度增长 |
| 直接展示生成的后续剧情文本再等待视频 | 不把候选后果显示为已发生；保留旧画面与真实状态 | 画面失败/偏离时不能产生互相矛盾的共同记忆 |
| 三视图+场景多视图+尾帧作为默认输入包 | 按用途与精确部署能力准入 | 输入类型/数量组合尚有文档冲突，尾帧也不是全部记忆 |
| 强制五秒、特定分辨率、附带声音能力 | 由已验证profile、表达长度、音轨能力决定 | 不把某次测试参数写成平台固定限制 |
| 点数预扣、失败统一退款、SKU/日期/营收 | 支付后续独立PRD；未知受理保留费用责任 | 供应商失败/超时不必然未计费，参考数字非我们的报价 |
| 商业恋爱游戏剧情来源建议 | 不作为默认素材来源；示例原创、用户设定优先 | 产品定位与素材来源都需独立确认 |
| 粉色像素/移动端视觉 | 借鉴场景主导，不照搬皮肤 | 当前桌面宽幅、浅色精致外部界面和单舞台已明确 |

## 4. 第一份需求稿内部尚未收敛的内容

- 9/10变更记录写“6个预设、一个剧本固定一个角色”；较早正文仍有“5个剧本×5个角色=25个开场”。这是版本未统一，不应把两套同时开发。
- 有段落强调不规定后续节点/结局，另有预设固定路线与终点的描述。应先冻结同一版范围再设计分支。
- “需求背景、用户核心路径、交互路径、交互说明”等栏目仍有空白，流程另标“待优化/编辑中/未定”。它是有价值的工作稿，不是完整验收规范。
- 模型测试、价格和时间目标属于文档当时假设；本轮没有验证其对本账户、地区或产品成立。

这些发现不否定材料价值，而是说明我们的PRD需要明确变更、单一范围基准和待定项，不把多次讨论叠成相互冲突的要求。

## 5. O01：模型附件与公开页面差异

截至本轮读取，比较如下；以下只是**两个文档的声明比较，不是接口实测结果**。

| 维度 | 用户附件PDF | 当前读取的公开页面 | 本项目决定 |
|---|---|---|---|
| 模型 | `MiniMax-H3-Max` / `MiniMax-H3-Max-Turbo` | 列出`MiniMax-H3` / `MiniMax-H3-Max`；本页未检出Turbo | 保留精确model ID及证据来源，不推断Turbo不存在 |
| Max输入 | 描述多模态参考图/视频/音频 | Max描述T2V/I2V首尾帧，不支持参考图/视频/音频模式 | 对冲突能力暂不准入，不把首帧与身份参考混为一谈 |
| Turbo参考输入 | 描述不支持参考输入 | 当前页未覆盖该型号 | 不复用Max能力配置，不凭名字自动降级 |
| 可配置项/价格/取消等 | 有对应描述 | 本轮核对重点为模型与输入，不声称逐项验证其他内容 | 参数/费用/取消能力需分别核对 |

公开页当时列Max为480P/768P、5–15秒；这个观察不将其他模型统一限制为该范围。来源：[官方视频生成接口页](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)。

**关闭O01步骤（研发/供应商接入负责）：**

1. 向材料提供方/供应商确认PDF原始发布位置、版本、适用地区/账户及是否预览接口。
2. 用官方控制台/正式文档确定准确endpoint、model、输入组合、输出/声音、计价和任务保留期；将差异落到能力证据版本。
3. 不更换既有连接的地区/身份来掩盖差异。每个连接与部署单独通过准入；未知能力保持关闭。
4. 先完成无付费契约与本地校验；真实试验另获明确费用上限后执行。记录实际请求、回执、媒体、费用、失败与查询恢复。
5. 更新Provider能力矩阵及Quote摘要，再启用相关交互入口。Mock通过和PDF存在都不能替代Gate B。

本轮未新增供应商、未切fal、未开付费调用，也未凭附件改运行时模型能力标记。
