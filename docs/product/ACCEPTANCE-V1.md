# V1 功能验收与需求追踪矩阵

2026-09-10 · 配套[PRD 1.9](../../FINAL-PRD.md)及[页面规格](PAGE-SPEC-V1.md)。**以下均为验收要求，不是已通过测试报告。** 历史原型、schema检查和Mock证据只能证明其对应层。

## 1. 使用方式与证据等级

- A：设计/交互原型，用来验证能否理解与操作；模拟数据必须标识。
- B：真实runtime、官方Provider与费用链；故障注入和真实供应商试验分别留证。
- C：正式Web/Tauri、两轮互动及退出重开；包含B的产品语义和可靠性门槛。
- M1/M2/M3/M4对应实施阶段。标“A→C”的用例需要先做原型走查，再在正式产品重验；A通过不抵消B/C失败。
- 每例记录：用例ID、构建/平台、前置数据版本、步骤、预期/实际、截图或脱敏日志、结果、缺陷链接、执行人和时间。未执行记“未执行”，不能从文档存在推断通过。

## 3. Gate与硬门槛

- Gate A：全部适用页面状态走查；5位目标用户至少4位无指导完成开始与首次回应。视觉主观评价另行记录，不以功能存在代替设计通过。
- Gate B：M2积累基础能力与故障证据，M3完成产品语义闭环后裁决。真实官方调用与Mock结果分表；≥30次独立语义试验，接受/拒绝/非选项均覆盖，其中至少3例按AC20覆盖非恋爱情境，≥27例相关回应。擅代重大决定/同意、重复创建、越预算、越权在测试集内为0；任一出现均阻断。模型能力、等待/成本分布、连续性阈值评审后冻结。
- Gate C：正式Web与Tauri重验适用用例，完成真实两轮、保存退出/重开、自动检查/事实归并和故障恢复；以Gate B冻结阈值验收，不临时放宽。
- 表中“B/C”表示在B验证底层机制，在C重验用户闭环；多平台不能只交一张浏览器截图。

## 5. 已知契约缺口与变更约束

AI辅助整理、字幕生成/对齐目前没有独立付费契约，不在原型里标作正式可用；用户可以手工完成P02。模型多参考输入能力冲突见[参考评估O01](REFERENCE-ASSESSMENT-2026-09-10.md)，相关入口经准入后才启用。

新增功能必须同时说明F/P/AC、API影响、数据生命周期、权限/费用、失败恢复和模型能力来源；设计稿增加按钮不构成需求通过。34例是功能基线，不是覆盖所有SQL并发与安全路径的穷尽测试集。
