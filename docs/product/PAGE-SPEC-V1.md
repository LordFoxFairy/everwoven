# V1 页面、字段与交互细则

配套[PRD1.9](../../FINAL-PRD.md)，2026-09-10。**设计规格，非原型已完成声明。** 页面ID是信息架构编号，不强制使用同名URL。F编号和[AC验收](ACCEPTANCE-V1.md)贯穿设计/研发/测试。

## 1. 页面地图与共同规则

| 页面 | 目的 | 主入口 | 默认主动作 | 离开去向 |
|---|---|---|---|---|
| P01 我的空间/经历列表 | 找到想继续或想创建的内容 | 应用首页、保存成功后 | 有经历：继续；空：创建起点 | P02或P06 |
| P02 剧本起点/模板发现 | 定义世界、选人物和开场 | 新建、我的剧本、模板 | 保存起点/准备进入 | P01或P05 |
| P03 角色管理 | 创建与复用稳定人设 | 我的角色、P02选角色 | 保存角色/使用此版本 | 原来源页 |
| P04 图片用途管理 | 选择并确认图片用在哪里 | P02/P03图片入口 | 确认用途 | 原编辑对象 |
| P05 开始确认 | 理解本次生成范围/费用 | P02准备进入 | 开始经历 | P06；校验失败留本页 |
| P06 视频现场 | 观看、回应、继续经历 | 开始成功/继续 | 按状态出现动作 | 保存后P01 |
| P07 恢复/异常层 | 明确已保存/未决/可恢复 | P06错误、重开核对 | 恢复/核对/保存离开 | 原现场或P01 |

P03/P04/P05/P07可以是覆盖层或独立页，设计时按上下文选；同一操作不重复出现两个语义不同的按钮。编辑模式允许表单滚动，游玩模式保持一块舞台，浮层内部独立滚动。

共同规则：服务端确认才标“已保存”；处理中按钮有明确禁用原因；异步结果绑定目标ID/版本；同名对象允许存在。返回关闭未保存编辑时提供继续编辑/保留草稿/放弃，按实际存储能力展示；不声称文字导出含图片。

## 2. P01 我的空间 / F01、F07

**当前实现映射（2026-09-10）：**导航名为「我的世界」，默认进入此页；个人首页只读本机记录，示例仍在独立「剧本广场」。当前浏览器演练按创建时间选取「最近开启」的一条，精确恢复已有演练checkpoint，不宣称最近活动时间或真实视频存档。无演练但有草稿时显示「继续创作」；全空才显示创建引导；读取失败显示保护状态而非伪空态。正式经历按下表的权威快照规则实现，尚未接通。

| 元素ID | 显示条件/内容 | 操作与结果 | 空/失败/边界 |
|---|---|---|---|
| P01.01 继续经历 | 最近有真实经历：名称、角色、上次停留摘要 | 读取权威快照后恢复P06 | 未决任务显示“核对中”；不新建任务 |
| P01.02 新起点 | 始终可见、清晰主次 | 创建全新编辑上下文进P02 | 清除旧剧本目标ID，防覆盖 |
| P01.03 我的剧本 | 标题、主要角色、保存时间、草稿/已用于经历 | 编辑/复制为新起点/准备进入 | 只有设定不显示“继续故事” |
| P01.04 提示模板 | 明确模板标签、初始情境简述 | 复制为可编辑草案，不复制后续节点 | 不显示虚假用户数、热度或播放量 |
| P01.05 整理与回收站 | 归档与删除区分 | 删除有范围说明；恢复校验生命周期 | 删草稿不删已冻结经历；删除经历先暂停 |

文案示例：空态“从一个想法开始”；只有草稿“继续编辑”；有经历“继续这段经历”。不把静态演示图或默认记录写成用户创建。

## 3. P02 起点编辑 / F01、F02

### 3.1 字段字典（产品名称→当前契约映射）

| 产品字段 | 含义/必填性 | 默认/来源 | 编辑及保存规则 |
|---|---|---|---|
| 剧本名称 | 必填；1–120字符 | 用户输入；空草稿可明确使用“未命名的世界” | `Story.title`；可重名；不偷偷改已有名称 |
| 想经历什么 | 开局需要可理解情境；保存草稿可留空 | 用户原文，AI建议需用户确认 | `settings.premise`≤12000；不是每轮玩家回复 |
| 我的身份 | 玩家在世界中的角色 | 原文提取后确认；缺失给就地提示 | `settings.playerRole`≤4000；不推断姓名、性别、爱情承诺 |
| 氛围 | 可选偏好 | 原文或用户选定模板 | `settings.tone`≤500；不是强制爱情路线 |
| 世界规则/边界 | 可选，长期约束 | 用户明确设定优先 | `settings.worldRules`最多30条、每条≤1000 |
| 主要人物 | 开局需一位主要角色 | 内置原创或自定义已保存版本 | `cast`首期UI一位；API容纳多槽不等于已验收多角色 |
| 此故事中的关系 | 与人物当前是什么关系 | 用户确认内容；空缺不默认已相爱 | `cast.overrides.relationshipToPlayer`≤2000；只属本剧本 |
| 人物在此故事的身份 | 情境内角色职责/处境 | 用户设定 | `cast.overrides.roleInWorld`≤3000 |
| 封面/开场参考 | 可选图片用途 | P04选择 | 对应`assets`槽；不靠图片文件名推断用途 |

字符上限以[API schema](../api/openapi.json)为准，前端提前提示、后端同样校验；不截断原文。字段是渐进披露：轻创建先一段原文，再集中确认；进阶编辑承载更多规则，而不是首次展示所有输入框。

### 3.2 行为规则

| 元素ID | 用户操作 | 系统动作 | 失败处理 |
|---|---|---|---|
| P02.01 原文编辑 | 输入/粘贴想法 | 本地编辑缓冲；保存时写同一StoryDraft | 超限就地提示，原文保留 |
| P02.02 AI整理 | 仅能力与独立授权用例已就绪才可用 | 生成带来源标识的草案，用户采纳后保存 | 暂未接入/调用失败保持手工编辑；不得假成功 |
| P02.03 保存 | 点击保存 | 版本校验后写入并显示确认时间 | 冲突保留输入，不静默覆盖远端 |
| P02.04 准备进入 | 已有可用角色/情境 | 固定当前版本，进入P05核对 | 缺项定位具体字段；不先收费 |
| P02.05 已玩设定再编辑 | 修改既有草稿 | 后续开局产生新版本/新经历 | 旧经历保持旧版本、旧人物与记忆 |

AI辅助创作是已有产品方向，但本次47操作尚无独立辅助创作收费API；在补齐契约前P02.02不可伪装可用，P02.01/.03/.04不受影响。

## 4. P03 角色 / F03

| 字段/元素 | 规则 | 映射或反馈 |
|---|---|---|
| 名称 | 1–80字符，可重名 | `Character.name` |
| 人设、身份、兴趣、习惯 | 统一描述，≤8000字符 | `settings.description`；兴趣不是无实现的新数据库列 |
| 说话方式 | ≤2000字符 | `settings.speechStyle`，以实际台词检验而非标签宣称 |
| 原则与边界 | 最多30条，每条≤1000 | `settings.boundaries`；不让默认模板覆盖用户明确边界 |
| 外观图片 | 可空，选择不外传 | `portraitAssetId`；真正请求支持性在P05验证 |
| 使用此角色 | 使用已冻结的CharacterVersion | 回到原剧本槽；不带其他经历共同记忆 |
| 保存/关闭 | 同草稿冲突/失败规则 | 关闭前明确保留还是放弃；不静默丢失 |

关系经历是“角色在本局与玩家的状态”，不是角色模板全局字段。角色模板修改不反向修改旧局；成年人关系题材的身份/边界要在开局可确认，不以真人照片替用户推断关系。

## 5. P04 图片 / F04

| 用途 | 用户需要知道 | 传输规则 | 异常 |
|---|---|---|---|
| 封面 | 用于我的空间/剧本展示 | 默认不发视频模型 | 封面丢失保留文字，不自动找替代真人 |
| 角色外观 | 希望维持人物外观 | 仅部署支持对应参考角色时发送 | 不支持时说明，不假装首帧就是身份参考 |
| 开场画面 | 希望以此场景开始 | 按图生模式/比例/格式处理；裁切或补边告知 | 处理后预览，不静默拉伸 |
| 前段衍生帧 | 用于下一段视觉承接 | 系统提取、记录来源，并进入报价用途说明 | 缺失/检查失败不自动重生成原视频 |

本机上传先验证JPEG/PNG/WebP真实解码、字节/像素上限；部署输入限制可能更严。UI展示实际配置限额，不把附件PDF的数字写成平台永久限制。

每次选图绑定目标编辑对象及操作版本；处理中阻止冲突切换或丢弃迟到结果。替换失败仍保留旧图；移除先更新引用，后台回收依赖引用和宽限期。原图/衍生图分开，不能通过一次替换修改旧经历素材。

## 6. P05 开始确认 / F02、F04、F08

| 必须展示 | 来自哪里 | 改变后 |
|---|---|---|
| 剧本、角色、初始身份/关系 | 用户已确认固定版本 | 回P02编辑并显式准备新的未开始经历，旧局不变 |
| 地区、供应商、精确模型 | Connection/Binding公开摘要 | 新绑定、新未开始经历、新报价；不修改旧经历或沿用旧授权 |
| 整段经历预算上限/币种 | 创建前由用户明确填写或确认的本地上限，不是供应商余额或单次报价 | 创建后不原地修改；预算耗尽仍可保存/核对 |
| 发送哪些图、用途、处理方式 | Quote.generationSummary.inputs | 输入包变化重新报价 |
| 画幅/规格/时长、声音模式 | 经部署准入的报价摘要 | 未知像素仅展示规格/比例，不猜width/height |
| 费用上界与覆盖范围 | Quote.maxCost/includes、预算摘要 | 过期/加价先重新确认 |

准备顺序：确认经历预算→保存/冻结角色及剧本→固定绑定→createExperience（零调用）→取得控制→quoteAction→展示确认。所有费用展示区分“经历总预算”与“本次最高费用”。开局素材/规格变化涉及固定设定或绑定时同样准备新经历；仅报价过期在原经历重报。旧未开始记录保留“待开始”，用户可明确暂停后删除；不自动覆盖或清空。详见[技术调用规则](../architecture/PRD-TECH-TRACEABILITY-V1.md)。

按钮语义：“开始经历 · 本次最高X”。用户确认时接受的必须是当前动作报价；请求超时先查回执，不换键催进度。无有效报价/能力/额度时禁用开始并提供明确处理方式；创建经历不是付费调用。

**交互一致性：** 每轮无需增加一个聊天式发送步骤。情境建议若已经展示对应有效报价，点击可直接完成回应授权；未获明确授权时用轻浮层确认。自由编辑改变动作则重新报价，费用尚未明确时不显示可直接发送的假就绪状态。不以“用户之前点过开始”授权无限后续调用。

## 7. P06 现场 / F05、F06

### 7.1 布局规则

- 一块video舞台占满浏览器内容区；无第二视频、常驻聊天侧栏或底部大表单。默认等比铺满，可切完整画面；不通过裁剪强行遮掉关键叙事信息。
- 顶部边缘保留返回/显示/更多，安静播放时减弱；指针/键盘焦点可唤回。退出、错误、焦点操作始终可达。
- 回应层悬浮在内容安全区域，可收纳/移动；默认避让不等于已做自动人脸识别。窄窗控件可缩并，浮层内可滚动，舞台尺寸不改变。
- 无障碍、系统全屏及减少动态效果按主PRD§8验收。全屏失败留在窗口，不丢状态。

### 7.2 按状态呈现

| 元素ID | 触发 | 显示/动作 | 不发生什么 |
|---|---|---|---|
| P06.01 等待层 | 开场/下一段任务已接受 | 真实阶段；有前段保留前段有效画面 | 不展示新候选剧情已发生，不虚构倒计时 |
| P06.02 播放控制 | 媒体检查通过 | 播放/暂停/音量（确有音轨）/显示方式 | 暂停播放不取消供应商任务 |
| P06.03 回应层 | 片段有效完成、事实/节点事务确认 | 正常2–4项建议+“自己回应” | 不按计时器或仅video ended在客户端直接造节点 |
| P06.04 建议项 | 当前节点且未消费 | 一击回应；独立修改只入草稿 | 不先弹聊天框；不写固定后续分支 |
| P06.05 自由回应 | 玩家主动展开 | 输入≤4000字符；草稿保存与发送分开 | 组字Enter不发；空白不发；旧节点不发 |
| P06.06 建议失败 | suggestionState=unavailable | “建议暂不可用，你可以说想说的话或描述行动”；自由入口/本地恢复 | 不移除节点，不伪造AI选项，不另收费重做视频 |
| P06.07 设置层 | 用户主动打开 | 音量/画面/有真实来源的字幕开关；可收纳 | 不退出现场、不修改世界、不重建任务 |
| P06.08 返回 | 用户要离开 | 打开P07保存状态，回执后导航 | 不立即销毁草稿或显示“任务已取消” |

收起回应层保留轻入口和未发送提示，不自动代选。片段完成前不剧透选项。场景行动以玩家实际输入为准，不因拒绝就强迫关系升级。

## 8. P07 保存/故障与重开 / F07、F08

| 场景 | 可见反馈 | 可操作 | 结果要求 |
|---|---|---|---|
| 正常保存离开 | “正在保存”；成功后“已保存” | 确认返回 | 最新草稿+已确认播放进度+暂停回执 |
| 保存冲突 | “另一窗口已更新，当前输入已保留” | 查看新状态、保留副本、重新确认 | 无静默覆盖/错误复活 |
| 双窗控制冲突 | 另一窗口控制中 | 显式接管或只读 | 接管不自动Resume/生成 |
| 提交结果未知 | 已接受情况正在核对，费用可能在途 | 核对/保存离开 | 不新增付费attempt |
| 已知失败 | 失败原因与可恢复动作 | 本地恢复或经新报价重试 | 原turn恢复，不二次消费节点 |
| 长期离线超查询窗口 | 结果/费用需进一步核对 | 受控核对、查看本地媒体 | 不把查不到当没扣费 |
| 重开终态失败 | 当前失败回合及可恢复模式 | 根据recoveryTarget继续 | 不依赖旧202或浏览器缓存 |
| 预算耗尽 | 已结算/预留/未决及剩余额度 | 保存、查看、核对 | 不用隐式备用供应商继续收费 |
| 素材缺失 | 文字/存档仍在，指出缺图/媒体 | 修复引用或支持的本地恢复 | 不换成默认人物伪装成功 |

## 9. 设计/研发交接要求

每个页面Figma/原型至少给出默认、空、处理中、成功、失败/冲突状态；适用时补窄窗与键盘焦点。标注P/F/AC编号和真实/模拟来源。未设计状态写明阻塞，不用一个“加载中”覆盖所有流程。

这次交付的是文字规格；现有3103未按本稿逐项重画。下一轮原型优先P05→P06→P07主链路，再完善P01–P04，不同时维护两套正式业务逻辑。
