# 二期提案：AI 对话与创作工作台

2026-09-10 · 设计提案，待确认；未实现，不扩大一期交付范围。

## 1. 定位

同一个本地优先产品内，增加独立的AI创作入口，不另建应用或端口。

- 玩：单视频舞台，按片段完成事件提供回应，沿用一期门禁。
- 创作：对话讨论、编辑剧本、定义角色、整理素材，逐步演进到画布。
- AI Chat：通用会话能力，同时服务独立对话页和项目内创作侧栏；不是两套聊天系统。

用户不需要为每种任务打开一个Agent页面。用户向一个创作助手表达目标，由单一编排入口选择能力；长任务展示实际步骤、结果与待确认事项，不展示内部推理链。

我们的产物是可进入游玩的世界、人物和开放开局；不是提前写完所有结局。画布中的关系线表达人物关系、设定依赖或素材引用，不默认成为固定剧情分支，更不等同于Agent执行图。

备选：纯Chat实现快但成果散落；直接做复杂节点编辑器可控但门槛高。推荐先“对话＋成果预览”，再让同一批成果投影成画布，避免返工两套数据。

## 3. 一套底座、两种创作视图

### 通用AI Chat主模块

- 独立会话入口：新建、历史、重命名、删除、消息与结果呈现。
- 文本流式响应、附件、停止、失败恢复、明确重新生成的费用；请求取消不自动代表供应商停止计费。
- 可不关联项目进行讨论；写入前显式选择项目/剧本目标。
- 明示当前上下文：已引用剧本、角色和图片；支持移除引用。历史列表可统一，模型上下文按项目和会话隔离。
- 普通讨论与创建/修改动作区分；纯聊天不自动产生项目对象。

### 项目内创作工作台

桌面：可收起的会话/项目导航＋AI对话栏＋主要成果区。成果区先支持文档/角色预览，后续切画布；宽度可调。窄窗口切换视图，不强挤三列。

- 在剧本编辑页点击“与AI打磨”，把当前版本作为明确引用带入会话。
- 对话产生剧本草案、人物卡、关系建议、场景/图片候选等结构化成果。
- 支持继续修改、对比变化、部分采纳、全部采纳、撤销为新版本；未确认结果只是候选。
- 画布以作品和素材为主体，工具按选中对象出现；不向普通用户默认暴露模型参数或工作流连线。
- 从已确认设定进入游玩；编辑新版本不反向改写已开始经历的快照。

## 4. Agent能力，不等于多个独立聊天产品

| 能力 | 输入 | 候选成果 | 应用边界 |
|---|---|---|---|
| 剧本打磨 | 原文、世界规则、用户修改目标 | 设定/开局修改提案 | 不擅自把开放互动改成固定剧情树 |
| 角色创建/修改 | 人设描述、明确引用的素材 | 人物卡及字段差异 | 创建新角色与修改既有角色分开确认 |
| 一致性检查 | 指定版本的剧本与人物 | 矛盾清单、定位及建议 | 只检查授权上下文，不跨项目偷带记忆 |
| 素材协作 | 图片引用、用户意图、模型能力 | 素材候选或生成任务 | 外传与付费生成单独确认 |

先一个创作编排入口＋受限业务工具。复杂任务确需分工时再引入子Agent，不按“每个按钮一个Agent”建设。LangChain/LangGraph为既定编排方向；Deep Agents是否引入，需按文件工作区、委派和持久任务的实际需求另做评审，不设为前置依赖。

## 5. 共用架构边界（目标，非已接通）

AI Chat组件 / 工作台 / 画布
→ 会话与任务接口
→ 单一创作编排入口
→ 受限的剧本、角色、素材工具
→ 现有业务Service
→ Prisma / SQLite

模型调用另经 Supplier → Model Binding → 能力适配器。文本、图片、视频共用供应商配置原则，但保留各自能力契约，不把聊天流和视频任务强行做成同一种API。

- 沿用现有Next/T3；会话CRUD/业务命令走类型化契约，流式事件通道单独评审，不假定普通query即能断线续传。
- 如采用Vercel AI SDK的UI/传输能力，只做呈现适配，不再引入第二个自主Agent循环。
- 普通用户不必理解AG-UI/A2UI协议。成果卡片使用受控schema与组件注册表，不执行模型输出的任意UI代码。
- Agent不直接改数据库；提出变更，用户采纳后通过同一个Service校验身份、目标、版本、幂等和预算。
- 画布节点引用业务对象ID/版本；位置、缩放和连线属于视图数据，不复制另一份剧本/角色真值。

## 6. 待评审的数据概念

Conversation、Message/MessagePart、ContextReference、AgentRun/ToolRun、ChangeProposal、CanvasDocument/Node/Edge。

此处只锁概念边界，不创建表和接口。后续评审再落实字段、索引、保留策略与迁移：沿用UUIDv7、createdAt/updatedAt/deletedAt/revision、无物理外键及真实唯一约束原则。Conversation不是游玩Session；聊天记录不是世界事实库。

## 7. 交付顺序

- 一期继续：本机受保护CRUD、官方供应商两轮视频生成闭环。不给未接通AI Chat做可点击的假成功入口。
- 二期A：共用Chat底座＋剧本/角色工具＋成果预览＋确认写回。先验证用户能用对话产出一个可玩的开局。
- 二期B：同一成果数据的画布组织、素材引用和关系展示；保留文档视图，不强制画布。
- 二期C：复杂任务委派、批量生成和更丰富素材协作，依实测收益和预算推进。

## 8. 最小闭环验收

用户描述世界 → 讨论打磨 → 生成角色/开局候选 → 查看改动 → 明确采纳 → 在现有剧本/角色页面读到同一对象 → 从确认版本进入游玩。

必须覆盖：拒绝不写入；重复采纳不重复创建；编辑期间版本变化触发冲突；断线不丢已保存消息且不盲目重发付费工具；取消执行状态如实展示；删除会话不级联删除已采纳角色/剧本；不同项目上下文隔离；在玩旧经历不被新草案覆盖。
