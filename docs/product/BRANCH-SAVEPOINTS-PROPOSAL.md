# 分支存档与时间线分叉 · 数据关系补充提案

2026-09-10 · 用户明确提出：回到上一幕或某个历史节点，作出另一种选择，保留原路线并产生树状后续。

状态：需求已记录，详细设计已补齐并进入技术方案1.2审查，见[技术专项](../architecture/BRANCH-SAVEPOINTS-DESIGN.md)与[审查记录](../architecture/DESIGN-REVIEW-1.2-2026-09-10.md)。当前只实现剧本根CRUD和浏览器单线演练恢复，未实现历史节点分支、正式Savepoint或对应数据库迁移。

## 1. 产品概念

用户看到的是“故事足迹 / 分支存档”。技术上是从不可变存档点创建新的经历分支，而不是倒带覆盖同一条历史。

这是一棵游玩时动态生长的经历树，不是预先编写的固定剧情树。建议选项和自由输入都能触发新走向；未选择的候选不预生成视频、不记作已经发生。

## 2. 四种动作必须区分

| 动作 | 含义 | 历史/生成影响 |
|---|---|---|
| 回看这一幕 | 查看已保存的历史视频与情境 | 不移动正在游玩的分支，不提交行动；不调用视频模型 |
| 继续这条线 | 恢复该经历当前进度 | 保持原经历身份；未决任务先核对，不盲目重提 |
| 从这里开启新走向 | 从明确存档点开始，重新作出选择 | 新建fork经历，原线路保留；此后首次生成另经报价授权 |
| 重试/重新生成 | 技术失败重试或用户要求另一个生成版本 | 失败且提交未知先核对；主动换版本是新生成操作，不覆盖旧视频及其后代 |

回看界面显示“回看中”，主操作“从这里开启新走向”；不要把历史节点上的按钮直接接到当前经历的respond，从而消费错误的节点。

## 3. 示例

```text
开场 → 他递来画册（可恢复存档点）
          ├─ 接过画册 → 原路线后续 → …
          ├─ 提议出门 → 新路线后续 → …
          └─ 用户自行表达 → 另一条后续 → …
```

每个已发生片段知道自己从哪个互动节点、哪次行动及哪次生成任务而来。选项文案不是节点ID；同一句话也可能产生不同结果。一个父节点可有多个子节点，parent不能加唯一约束。

## 4. 与现有架构保持一致

沿用ARCHITECTURE中“显式fork经历、禁止覆盖已发生记录”的裁决。一次Experience仍固定设定/人物/模型配置和自己后续的进度；分支树是相关经历及节点的组合视图，不把所有路线塞进一个可变的全局世界状态。

计划中的逻辑对象（字段名为候选，M2/M3建模时冻结）：

| 对象 | 必须保留的关系/内容 |
|---|---|
| MediaSegment / 已发生节点 | 本经历、来源互动节点、来源TurnRun、上一片段/来源节点、媒体Asset身份与hash、生成/验证记录 |
| Savepoint / 可恢复存档点 | 对应节点、固定设定/人物/绑定版本、当时已确认的世界状态、角色可知事实、可回应情境、快照schema版本 |
| fork Experience | sourceExperienceId、sourceSavepointId、同owner的明确来源；独立状态、控制权、未决操作与预算授权 |
| 分支进度 | 当前经历的有效节点、已消费的互动与未发送回应草稿；浏览回看的位置不等于这个进度 |

不是复制一个可变“记忆摘要”即可恢复。状态可用不可变快照＋该节点之前的事件引用实现，后续可评估增量快照；不得只靠聊天记录或视频URL重建。业务Savepoint也不等于LangGraph的任务恢复checkpoint。

不把M0的setup InteractionEvent当作已发生视频节点。正式分支需显式建立新的可回应身份；后续API仍拒绝在原来已消费的互动节点上再次提交。跨经历复用前缀仅允许经验证的fork来源，不能因此放宽所有节点的同经历/同owner校验。

## 5. 一致性与安全边界

- 自动存档点建议落在“视频有效、完成观看、事实检查通过、回应节点可用”这一稳定边界。生成中/失败/未看完不是同一种可分叉状态。
- 从节点分叉只携带该节点及之前的已确认状态，不携带原路线之后的行动、关系变化、角色记忆或玩家未发送草稿。
- 原片段、已消费行动与其后代不可覆盖。改过的设定/角色版本不悄悄影响旧路线；跨配置分叉另行确认兼容性。
- 创建fork本身零模型调用。用户提交新选择后才生成，不因打开故事树、悬停或点回看就付费。
- 预算、报价与许可不从旧分支照抄；已受理原任务不因切分支自动取消或退款。账户总预算不可通过分支复制被扩大。
- 视频/图片文件尽量引用共享，不整棵复制媒体；分支删除不是立即物理删除共享素材。仍由存活引用、备份pin、未决操作与宽限期决定回收。
- 禁止物理外键；来源存在、owner、可引用状态、祖先范围、无环和分支进度CAS由应用事务保证。所有来源查询建立有实际消费者的普通索引；不把parent/sourceSavepoint设成唯一。
- Fork命令幂等，同命令只产生一个新经历；不同命令可在同一Savepoint合法产生多个分支。

## 6. 分期裁决建议

- 一期数据建模：MediaSegment/TurnRun/InteractionEvent/Savepoint落地时明确来源链与不可变状态，不只保存“最后一段视频”。这不是立即改M0草稿表。
- 一期体验：先做好单条经历生成、保存、重开；进度门禁与未决任务核对不因分支需求省略。
- 扩展体验：历史回看、从存档点fork、命名/切换分支；是否并入首个可玩版本需单独确认，不悄悄扩大P0。
- 更后续：完整可缩放故事树、分支对比与更多整理方式。普通游玩时入口收纳在“故事足迹”，不常驻复杂工作流画布。

## 7. 后续验收用例

1. A→B→C之后从B开新走向D，A/B/C完整保留，D不含C之后的记忆。
2. 同一fork命令重发仅一个新经历；不同命令允许两个合法分支。
3. 新线中编辑回应、失败/重试、退出/重开，不改变原线进度、草稿或已确认事实。
4. 回看不创建任务，不消费当前节点；取消分叉或预算拒绝不产生收费调用。
5. 未看完/未决生成节点给出真实限制，提交未知任务先核对，不通过“分支”绕开核对。
6. 共享视频缺失时明确提示；不假装通过重新生成恢复原视频。删除分支不误删仍被另一分支引用的素材。
7. 伪造sourceSavepoint、跨owner来源、环、失效版本以及旧进度CAS均被拒绝。

本提案没有创建表、实现分支按钮或宣称原型已经支持读档分叉。
