## 主链路：只用现有产品页面

1. 同一个Next应用，正式模式在原角色库连接本机；禁用浏览器localStorage和IndexedDB业务读写，不因失败切演示。
2. 原表单创建角色，输入姓名/性格背景/外貌/表达/边界；就地选择真实图，确认权利后上传，再保存角色引用。
3. “用TA创作”进入原Editor，填写标题/题材/世界/开局/玩家身份/规则/语气/初始关系；选择封面和开场图。配置切换不丢上传或未决命令。
4. 保存一个完整聚合：父revision、固定角色版本、初始关系和覆盖、三图片槽。角色库来源与剧本固定副本互不回写，图片槽与portrait覆盖只有一个真值。
5. 从原“我的剧本”重新打开；关闭页面、重启服务、再次连接，全部字段和真实图片恢复。不得从测试面板或浏览器Mock冒充恢复。
6. 修改世界、角色副本和图片后保存，根revision只增加一次；独立读取源角色证实未被修改。返回列表、软删除、回收列表恢复后内容和引用不变。
7. 断网/丢响应保留原commandId及payload，确认历史结果不覆盖用户后续输入；继续保存才写后续编辑。未知命令禁止新建/离开导致重复创建；没有后台自动重试副作用。
8. 数据集更换保留文本但清空旧根/来源/图片身份，明确从文本新建；旧响应不落新表单。未连接、真正空库、读取失败三种状态不同。

## 故障与一致性证据

| 场景 | 必须证据 | 执行层 |
|---|---|---|
| begin/complete/create/update已提交但响应丢失 | 原命令重放、一份业务实体/回执、新文本仍保留 | 真实Next+Chrome；非仅mock |
| 后续请求在receipt前被400拒绝 | 已有unknown继续保留，原命令仍能确认 | Controller与原UI生产回归 |
| 旧模板修改或删除 | 已保存剧本固定角色不漂移，后续新绑定核验当前修订 | 实际SQLite+原页面 |
| 旧资产后来unavailable | 历史文本仍可读取/编辑，图片明确失效；新绑定拒绝 | 用例+组件 |
| 事务中版本/关系/回执任一步失败 | 根、内部模板、版本、三槽、回执全回滚 | 实际SQLite故障注入 |
| CAS/owner/dataset/非法bound | 无越权读取/绑定、无部分提交、原输入保留 | 用例/HTTP/Controller |
| 软删除/恢复 | 不改固定版本或删除文件，旧回执不拼当前资源 | SQLite+原UI |
| 临时残留维护 | 默认预览；有界明确执行、lease/历史引用保护、一次性凭据撤销 | 真实CLI+既有T2进程测试 |
