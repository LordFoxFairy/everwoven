# 个人入口与现场连续性 · 实施记录

## 本轮设计
沿用已确认的单一 3100 入口、晴空浅蓝与淡紫视觉，不另起原型。下一代交互的判断标准是用户能否自然接续自己的经历，而不是装饰多少 AI 符号。

- 默认「我的世界」：有演练记录时突出一个可恢复入口；没有记录时使用创建引导。剧本广场独立作为灵感入口。
- 首页只读取用户本机数据，不把示例剧本、假关系值、假 AI 记忆混入个人空间。
- 按创建时间呈现「最近开启」而非声称「最近玩过」；旧数据没有活动时间，不新增伪精确字段。
- 一次恢复沿用原记录 ID 与 checkpoint，不调用 newSave，不自动提交草稿；只在显式开始新演练时创建新记录。
- 状态文案区分待回应、静态参考、演练失败、准备中、没有 checkpoint 的旧记录。静态图不称为视频封面或已生成场景。
- 现场仍为生成→观看→回应；确认覆盖草稿或离开时，用页面内原生 modal dialog 管理焦点与背景交互，不用系统 confirm。

## 实施计划
1. 为首页数据派生与真实空态写失败测试。
2. 实现无副作用派生器、个人入口及局部样式，接入现有 Platform。
3. 完善现场确认的模态语义和键盘行为。
4. 运行全套测试、类型检查、构建；在独立临时标签页检查宽窄屏、导航和恢复入口。
5. 写明验收结果与尚未接通的能力，不把 Mock 演练等同于真实生成。

## 不在本轮
真实 MiniMax 调用、自动语音、后台世界自主运行、SQLite UI CRUD、云同步、点击物体。以上继续遵循现有供应商-model 架构与后续里程碑。

## 下一代产品感：本轮采用的判断，不是能力宣称

1. **我的上下文优先**：打开应用先回答“我可以接着做什么”，不是反复营销同一组角色。
2. **主动作随状态变化**：未发送→继续写；待回应→选择方向；失败→先查看再重试。相同按钮不掩盖不同结果。
3. **画面承载经历，界面承载意图**：故事现场只保留一个媒体舞台，工具和确认属于可退后的浮层；不把聊天记录当主舞台。
4. **用户有最终决定权**：没有自动发送、自动收费或假自主剧情；替换草稿先确认，取消回到原位置。
5. **能力必须有证据**：演练状态只说明本地状态；下一阶段应以两轮真实生成中可观察的行动后果、角色连续性和恢复能力验收，而非以颜色或动画验收“AI”。

## 本轮变更

- 新增 `WorldHome`：未读失败/全空/只有草稿/已有演练分层。使用现有图片解析，上传素材缺失不偷偷替换成默认角色。
- `rehearsal-resume` 为纯展示派生，无存储写入、模型调用或数据库依赖；按创建时间比较并保留原对象，非法旧日期低优先级。
- `Platform` 默认home，品牌/侧栏/首页列表入口共用导航重置，防止上一页面的筛选造成伪空列表。
- `StageConfirmation` 在stage内部用 `showModal()`，默认聚焦安全动作，双向Tab循环，Escape只取消当前确认，关闭后归还焦点。保留草稿、替换草稿、直接改用建议发送的语义分开。
- 没有新增依赖、数据库列、第二入口、模型请求或真实付费路径。

## 验证记录

- 自动测试新增12项：首页空态/错误态、草稿、创建时间排序、旧记录兼容、阶段动作与modal语义；共22文件198项测试通过。runtime/Web类型检查、生产构建通过。
- 独立临时浏览器标签页，未操作用户正在编辑的标签页。桌面1280px查看个人首页；390px与320px实测文档宽度等于视口宽度，320px主内容无元素越界。
- 从首页恢复既有未发送草稿：仍为原文，未发送、未追加回合；退出后10条既有演练记录保持10条，最近记录仍为1条行动。
- 替换建议和直接发送另一建议均先确认；均取消后，原稿未变化。Escape不顺带收起回应面板，焦点回到触发按钮。
- 初次浏览器测试发现Tab离开dialog；补双向焦点循环后复测通过。800×450低矮窗口确认框边界在视口内。
- 只读审查发现品牌→首页→探索继承旧筛选；实测复现后统一导航逻辑，复测关键词为空、4张示例卡恢复。
- 本轮浏览器没有改写用户草稿、提交回应、上传图片或调用模型。尺寸覆盖已撤销；临时检查页在结束时关闭。

### 尚未覆盖 / 下一阶段门槛

- 模态进入系统全屏后的平台差异尚未专门实测；结构保持在stage内部。
- 存储失败在首页用组件测试覆盖，未在用户浏览器故意破坏或替换存储；短屏保存失败叠层的完整故障注入仍待独立测试。
- 这不是“下一代产品已完成”的结论。下一工程切片仍应接通本机身份与受保护数据操作，再验收官方供应商的两轮生成闭环及实际等待体验。
