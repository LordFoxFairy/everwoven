# 官方视频供应商：第一个真实闭环实施计划

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 先证明官方 MiniMax 下“自动开场 → 用户行动 → 后续视频实际响应”的协议与媒体链路，测清片段式生成是否能满足交互体验；不把契约测试当成真实生成通过。

**Architecture:** 新增有限视频任务契约，与现有 LiveVideoProvider 分开。MiniMax 适配留服务端，由受预算约束的运行时调度；客户端继续使用独立媒体呈现。第一阶段只实现离线可测适配和输入计划，不开放未经预算/身份保护的付费路由。

**Tech Stack:** 当前 TypeScript、Vitest、Next.js；供应商—模型目录复用现有结构。叙事层后续沿用 LangChain/LangGraph 唯一编排，暂不新增第二 Agent 或 UI 协议依赖。

---

## 约束与完成边界

- 产品基准：[FINAL-PRD](../../../FINAL-PRD.md) 1.3；节奏基准：[世界会等你](../specs/2026-09-09-world-rhythm-and-agency-design.md)。
- 此计划是技术验证切片，不覆盖完整身份系统、社区、Tauri 或所有动态卡片。
- 没有费用明确的授权时只运行本地模拟响应与测试，不读取密钥、不自动调用供应商。
- MiniMax 官方与 fal 为不同部署；不以 fallback 让测试“成功”。
- 不借本轮重写角色库或素材数据库，不更动用户的本地草稿。
- 现有 `catalog.ts` 的官方部署不就绪状态，在真实连续播放与预算门禁通过前不改成可开始。

## Task 1：输入契约与素材模式（不发网络请求）

- [ ] 实现前重新核对官方创建/查询文档：真实 model ID、输入组合、帧/参考模式、尺寸/比例、响应状态和请求限制；记录核对日期。
- [ ] 写失败测试：封面永不成为模型输入；角色参考与首帧不混发；未知部署失败；模型不支持的角色图不静默忽略；浏览器 blob URL 不作为远端素材地址。
- [ ] 运行定向测试确认预期失败，再实现纯输入计划函数。冲突返回明确的待选择原因，不直接决定丢弃哪张图。
- [ ] 覆盖无图片、角色图、开场图、两类同选、元数据缺失与错误比例；区分本机保存规范和供应商规范。
- [ ] 运行 `pnpm test` 与 `pnpm typecheck`；确认没有修改实际环境变量或产生外部请求。

## Task 2：有限任务适配器（全部使用注入的假网络）

- [ ] 写失败测试：供应商—模型准确映射、创建成功、查询到终态、未知/畸形响应、401/429/5xx、超时、轮询终止。
- [ ] 实现服务端专用 adapter，真实凭证由调用方服务端注入，测试仅使用测试字符串；客户端模块不得引用该 adapter。
- [ ] 分开本地请求中止和供应商任务取消：AbortSignal 不冒充远端取消成功。
- [ ] 提交超时/连接异常视为结果未知，不自动重复 POST；查询重试有次数/时限和退避。
- [ ] 官方不具备的取消、暂停、用量字段不编造；对原始供应商错误日志去敏，用户错误中不回传凭证或私密请求内容。
- [ ] 覆盖按允许区域选择官方地址，禁止传入任意上游主机；输出 URL/结果有效性按官方规则验证。
- [ ] 主工作区执行全部测试、类型检查和生产构建；只有这些通过不算真实 Provider 验收通过。

## Task 3：受限真实技术验证（等待明确预算授权）

- [ ] 先确认所选部署费用上界、在途任务和重试成本可纳入预算；无可靠上界不执行。
- [ ] 由用户在本地配置对应供应商凭证，确认具体预算与允许的测试次数/时长；不把“继续打磨”视为付费测试授权。
- [ ] 使用非私密的测试设定和素材，先验证一段真实开场。记录请求、任务状态、输出可播放性与费用；当前生成内容未校验前不当作正式玩家现场。
- [ ] 以相同初始情境分别测试两个相反行动，检查结果是否体现差异；随后测试一次连续改主意和一次关键事件等待。
- [ ] 分别记录输入确认、调度、首帧、关联后果播放、语义是否符合、衔接断裂和费用。缺少供应商指标时标明未取得，不由客户端猜测。
- [ ] 验证首帧/角色输入模式与角色外观连续性；本机上传成功不算通过。
- [ ] 若只能得到独立慢片段，记录未达到产品目标并复议模型/调度方案；不通过改文案验收。

## Task 4：达到技术条件后再接入正式现场

- [ ] 另行细化服务端身份、预算预留、故事写入版本和会话归属，再开放可计费入口；不直接将 adapter 暴露为无鉴权 Next 路由。
- [ ] 写过期候选不上屏、关键决定预播门禁、提交结果未知不重试、结束与保存分离等失败测试。
- [ ] 接入真实媒体，不用静态图/重复对白伪装等待；与现有自由表达共享 PlayerIntent，不形成另一套聊天入口。
- [ ] 剧情事件在实际呈现证据与校验后显示对应卡片。校验带来的延迟必须纳入端到端指标。
- [ ] 浏览器验证自动开场、三次自由介入（含拒绝建议、改方向）、无输入等待、错误、退出；保留已有用户数据。
- [ ] 将真实结果与未完成项写入验证记录，随后才冻结轻量创建与续接体验的高保真设计。

## 后续入口优化（不抢占真实闭环验证）

“一句体验描述 + 可选角色/图片 → 可编辑的设定草案 → 确认进入”。复用当前 Story 字段；AI 整理未接入时保持手工填写，不生成假结果。详细编辑、角色库和素材库作为进阶创作空间保留，不再要求普通用户必须走四页管理表单。

## 当前原型复核：规划可执行，不等于原型已完成

- 本次重新执行：37 项单测与 TypeScript 检查通过。没有重新执行生产构建，也没有真实模型调用。
- 当前浏览器编辑页仍为四步表单；轻量创建尚未实现。窄窗口可见主流程，但这只能证明该页呈现，不等于双端全流程验收。
- 本轮尝试离开编辑页时触发未保存确认；没有接受舍弃。浏览器自动化的取消接口超时，原页面保留，不以刷新清空草稿完成走查。
- 主 PRD 已统一产品方向；主要缺口不是继续增加需求，而是官方视频闭环、事件与已呈现画面联动，以及经历状态的可靠续接。
- 可保留：角色/素材编辑、本机保存、初始设定快照。
- 待改：普通用户的四步表单负担、详情与准备的重复过渡、准备记录和真正游玩经历的区分。
- 尚不成立：把现有原型认定为可玩的实时生成游戏、精确恢复视频现场、已完成桌面适配。
- 下一轮仍先执行 Task 1/2 的官方素材输入计划与有限任务适配测试；独立完成、不触发付费。随后取得具体测试预算，再执行 Task 3，而不是继续只写规划。
