# 默认铺满游玩区域，一键进入系统全屏

依据：用户确认“画面就是整个界面”，不是页面里一个放大的播放器。此设计更新默认 contain、留边、圆角及底部固定评审栏要求；不改变一期分段互动。

## 三个不同概念

1. **默认铺满窗口**：单舞台从 (0,0) 覆盖整个浏览器内容区，无外框、外边距、圆角或下方功能栏。媒体 cover 保持比例，可能裁掉边缘。
2. **完整画面**：用户一键切换 contain，恢复整个原始构图，比例不同时允许留边；用于观察边缘人物、物体和线索。
3. **系统全屏**：明确点击按钮调用浏览器原生 Fullscreen API。不同于 CSS 高宽变大，不自动强占屏幕；状态按真实浏览器事件同步。

不改变模型生成尺寸，不重启生成，不把视频拉伸。显示选项不改故事事实、草稿或待决定事件。默认 cover 的边缘裁切有可见说明，不承诺自动保住所有人物。

## 控件与沉浸

- 顶部轻量浮层：退出／故事标识、完整画面切换、全屏、设置。
- 片段结束自动出现建议；可收起、换边、自主回应。选择后收回，只显示下一段生成的真实阶段。
- 观看和生成中无实时介入入口。
- 静态原型及 AI 身份标识保留；评审工具缩成右下浮动入口，不再占据40px横栏，正式产品不带。
- 错误独立于回应收纳，始终有恢复与退出路径。
- 小窗口控制条与回应区分别约束，不因铺满而让按钮溢出或遮住退出入口。

## 全屏生命周期

参考 [MDN requestFullscreen](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)：原生调用需要用户操作；请求可能被宿主拒绝；通过 fullscreenchange 与实际状态更新标签。

使用 documentElement 作为原生全屏根，确保当前原型的设置与退出 dialog 仍位于全屏树内。没有使用键盘锁；全屏时 Escape 留给浏览器退出，不同时吞掉按键收起回应。

进入失败或宿主未开放时显示说明并保留铺满窗口，不谎报“已全屏”。明确离开现场时先退出原生全屏，再返回外部页面；退出异常保留现场并说明处理方式。

## 验证

- 先写显示偏好与原生全屏测试：旧实现默认／切换两项失败、原生模块缺失；补齐后相关27项通过。
- 1440×900 浏览器实际测得舞台 [0,0,1440,900]，圆角0，默认 cover。
- 点击完整画面后为 contain，舞台仍1440×900，情境选项保留。
- 实际点击全屏后按钮切为退出全屏，DOM `:fullscreen` 匹配 HTML；全屏内设置对话框可打开和关闭，点击退出全屏后按钮恢复进入全屏。
- 上述仅验证显示与原型交互，不代表真实视频生成、音频、成本与流媒体连续性已接通。

窄窗口细节：本轮示例人物的裁切焦点按原图构图人工设为横向72%，避免默认居中把脸切到边缘；用户自选图片保持居中，尚未实现自动人脸识别或素材焦点编辑。完整画面入口始终保留。507×800检查舞台与页面均为507×800，无整页溢出。

最终检查：主仓121项测试、类型检查、Next生产构建通过。最终507×800截图确认示例人物面部留在画内；这只验证该样例人工焦点，不泛化为任意视频自动裁切保障。页面仍为静态原型，未进行付费模型调用。
