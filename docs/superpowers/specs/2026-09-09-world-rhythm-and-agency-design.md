# 世界会等你：实时视频游戏的节奏与玩家主动权

日期：2026-09-09
状态：目标对齐稿；记录产品建议及其理由，不代表已实现或已完成真实模型验收。
范围：补充一期自由介入与情境触发设计，不扩展本轮实现范围。
关联：[现场体验基线](2026-09-08-live-world-experience-design.md)、[供应商—模型边界](../../PROVIDER-MODEL-BINDING.md)。

## 1. 用户意图与当前决策

用户要求继续思考下一代产品形态并记录，特别确认世界是否等待下一步点击事件或回复。

已经确认的目标：用户自定义剧本、角色和素材，进入实时生成的视频现场；不是固定剧情影片，也不是视频旁边的 AI 聊天。自由表达是主要入口，动态卡片按当下情境触发，画面物体点击留到二期。

本稿推荐的一期默认：**事件驱动的等待。世界可以有自然的表现，但涉及玩家的关键决定必须等玩家。**

这不同于每段视频播放结束都强迫用户回答，也不同于用户沉默时无限推进、无限计费。

仍待体验验证的建议：具体等待表现、多久提醒、是否需要主动推进模式、可接受的响应延迟和每次体验预算。不得将这些建议当成已批准的数值指标。

## 2. 三种节奏方案

| 方案 | 优点 | 代价 | 本次建议 |
| --- | --- | --- | --- |
| 每段结束等操作 | 易理解、容易限制生成任务数量 | 像逐段点播；视频片段边界决定游戏节奏 | 不作为产品定义；技术上暂时停留要如实显示 |
| 世界自行持续推进 | 强烈的持续发生感 | 容易错过决定、角色替玩家做主、无输入仍消耗预算 | 仅作为未来用户主动选择的玩法，不作默认 |
| 按有意义的事件等待 | 自由介入与玩家主动权兼容，剧情节奏不绑定模型片长 | 需要状态、生成边界、播放时序和费用约束 | 一期默认推荐 |

## 3. 等待的不是每句话，而是需要玩家参与的事情

将三个“时钟”分开：
- **表现时钟**：视频、人物微动作、环境声音是否仍播放。
- **剧情时钟**：新事件、关系变化、线索和场景迁移是否继续发生。
- **生成/费用时钟**：供应商是否仍在执行或维持计费会话。

剧情等待不等于暂停播放，也不等于已经停止计费。静音与暂停画面都不作为停止生成的依据。

| 当前情况 | 可以继续发生 | 必须等待或禁止 |
| --- | --- | --- |
| 开场、一次已经决定的动作执行中 | 已授权动作的结果、相关对白、环境表现 | 不自动承接为下一项玩家决定 |
| 人物向玩家提问或发出邀请 | 低强度等待表现；自然停顿 | 不替玩家回答，不因为沉默默认同意 |
| 玩家正在输入 | 有限环境表现 | 不撤下仍相关的互动，不抢先推进决定 |
| 玩家明确说“继续看看” | 当前情境内的一小段自主表现 | 不把一次指令视为长期自动选择授权 |
| 长时间没有回应或页面离开前台 | 保留当前待决定事件，收敛新任务调度 | 不无限生成等待片段，不自动重复催促 |
| 发生生成/网络故障 | 明确显示故障与恢复入口 | 不把技术故障解释成角色故意沉默 |

“长时间”在一期以配置项记录并通过测试确定，不写死成用户尚未认可的节奏；预算硬限制不因配置等待时长而失效。

## 4. 产品形态如何体现

### 平台与创作
- 剧本不是逐句脚本，而是世界初始条件、人物动机、玩家身份、边界和开局。
- 不要求创作者填写几十个触发器才能开始；高级事件规则以后渐进开放。
- 角色的主动性来自其动机及情境，不等于替玩家决定感受、台词或行动。
- 创作助手可以补全缺项，但需用户审阅后才写回正式设定。

### 现场
- 默认看到世界，不看到一个等待提问的聊天助手。
- 问题已在视频中出现后，才有资格呈现相关轻量交互。
- 选项数量取决于事件；可以没有选项。建议不应冒充穷尽所有可能。
- 用户可以接受、拒绝、提出第三种做法，或暂时不作答。
- 自由表达保留可发现的入口；输入层只服务本次行动，不变成聊天记录主界面。
- 一期点击是语义事件操作；二期画面点击才需要坐标、帧证据与物体身份。

### 叙事表达与创作指令
- “我去窗边”是玩家行动；“把角色性格改成外向”是修改设定。
- 默认以玩家行动理解现场输入；明显的设定修改通过明确的编辑确认进入创作流程，不悄悄改写世界。
- 过去已发生的事实不因一句新提示直接被抹掉。未来重演/分叉须单独定义。

## 5. 一个完整的体验片段

以下是内部验收情境，不是平台内置固定剧情，也不承诺具体生成时延。

1. 用户配置书店、人物和开局，点击开始。人物自然完成开场动作，无需用户先发消息。
2. 人物问：“要坐窗边吗？”此邀请对应的画面/对白开始呈现后，事件进入等待。
3. 用户可以看到少量相关建议，也可以自行说：“先不了，我想看看你手里的书。”
4. 用户暂不回答：邀请保持有效，世界不直接跳到两人已经坐下。若有经验证的等待表现可短暂使用；否则诚实停留当前画面。
5. 用户提交表达：界面确认收到；这不是画面已响应，也不立即写入“已经拿到书”。
6. 下一段真实视频表现人物回应。只有与实际呈现及经过校验的事件一致的结果才提交为世界事实。
7. 用户接着说“我们出去走走”：即便没有新按钮，也能主动提出新方向。尚未呈现的冲突计划或候选输出可作废，已呈现且经校验的事实保持不变；已产生的生成费用不会因此自动退回。

核心体验：**等待不催促，主动不越界，回应有结果。**

## 6. 面向研发的最小契约（建议设计，非现有实现声明）

### 叙事节拍与视频片段分离
一个 beat 是一次有意义的情境变化，可以跨多个媒体片段。长期允许片段内事件，但一期关键决定点必须落在可控的播放边界：视频时长由模型约束，不能反过来强迫玩家按片长作答。

**一期关键决定的播放门禁：**
- 待生成的节拍只到“提出问题/邀请并等待”，不包含玩家尚未选择的结果；提示约束只是第一道措施，不视为可靠保证。
- 包含关键决定的候选片段须在首帧上屏前完成整段语义检查，确认不存在越过该决定的动作或对白。校验是待实现、待实测的能力；不确定或发现越权内容的整段不上屏，在预算内重试或保留当前现场并提示未能继续。
- 一期不依赖不精确的时间定位临时截断对白，也不把“视频已经显示、但没有写入状态”当作保护。
- 没有可靠预播校验时，不允许把含关键决定的候选视频直接播放并宣称已实现玩家主动权保障。普通已授权表现也受世界一致性校验约束。
- 这会增加端到端延迟，必须一起测量。若达不到双方随后对齐的交互延迟标准，视为一期核心体验未通过，回到模型或生成调度选型；不把逐段漫长等待包装成实时成功。

### 事件
每个可交互事件至少包含：
- eventId、sceneRevision、beatId；
- 呈现锚点：clipId 与媒体时间范围或经验证的呈现事件；
- 意图与可选建议，不包含任意可执行模型代码；
- 是否需要玩家决定、失效条件、冲突范围；
- 状态 proposed → presented → awaiting → resolving → resolved，或 expired / withdrawn。

accepted 是输入状态；resolved 是事件状态；played 是媒体状态，三者不可混为一个成功布尔值。

### 统一玩家意图
自由文字、卡片点击、未来语音、未来空间点击统一落到 PlayerIntent：
intentId、source、关联 eventId（可空）、sceneRevision、内容、提交时间、基于何时的可见画面。
- 自由输入不要求挂靠当前卡片事件。
- 旧卡片点击重新验证有效性；过期则解释并保留用户表达，不重复执行。
- 使用幂等 ID，防止双击、重连或重试触发重复任务与重复扣费。
- 玩家打字不是已提交行动，也不是授权下一段关键剧情。

### 用户先回答、画面尚未播完
不必强制等演员说完才接受输入。可以先保存行动。这里的“已承诺”仅指已经实际呈现的内容，不以任务提交、生成开始或供应商返回结果作为剧情承诺。

| 原计划阶段 | 冲突的新行动如何处理 | 旧内容与费用 |
| --- | --- | --- |
| 尚未调度 | 新方向替换；补充信息可合并 | 不再提交旧计划 |
| 已调度/正在生成，尚未播放 | 提升生成版本，使旧候选失效；尽力取消 | 旧结果即使晚到也不上屏、不提交事实；在途费用仍计入 |
| 已生成但未播放 | 作废不再播放，按新方向调度 | 已发生费用保留；不以节省费用为由强播冲突片段 |
| 已开始播放 | 保留已呈现部分；在最早可验证的安全边界切换 | 尚未呈现部分不必完成，但若缺少可靠截断边界，一期允许播完已授权且通过门禁的当前片段，明确新行动影响后续 |

所有候选片段带生成版本和来源行动 ID；首帧播放前再次检查是否仍为有效版本。用户提交时收到接收反馈不等于已经完成切换。已开始播放的片段允许继续的前提是不跨越尚未决定的关键节点；第 6 节播放门禁优先。

### 生成预测与实际呈现不一致
计划中有人发出邀请，实际画面没有出现或没有可靠证据：不显示该邀请的确定性事件卡，不提交对应事实。可保留不声称画面事实的自由表达入口；继续生成或恢复时先处理一致性问题。

## 7. 等待与预算：不靠无限生成维持“活着”

能力按照供应商—模型的实际部署登记，区别原生能力与应用层实现：
- 是否支持生成期间更新指令；
- 是否能取消任务或可靠结束会话；
- 是否能暂停生成，以及暂停是否仍计费；
- 是否支持帧续接与可验证的媒体/事件关联；
- 等待表现与同场景连续性是否经过实测。

这些字段是待核验的能力设计，不是对现有供应商能力的宣称。

**一期成本准入门槛：**只接入可在请求前确定最大费用的有限任务，或具备供应商服务端硬性时长/费用封顶及可验证终止边界的会话模式。仅有客户端停止按钮、无法界定取消延迟的停止接口不算费用硬封顶。未通过准入的部署保留在研究目录，不开放一期付费开始入口。

服务端调度前原子预留该请求的最坏费用（包括最低消费、所有并发在途任务和可界定的终止尾部费用），满足“已结算＋已预留＋本次预留 ≤ 用户授权预算”才发出请求。取消结果未知时保留预留，不释放后重复花费；供应商不支持可靠幂等时，不盲目重试提交状态未知的生成请求。若最大费用无法确定，则不提交该请求。

一期建议执行纪律：
1. 等待玩家决定时，不提交任何依赖尚未作出选择的后续剧情任务。
2. 等待用的生成表现只能有明确预算与上限；默认关闭未经验证的无限 idle 生成。
3. 短期等待若使用本地环境声或保留画面，应与真正新生成的视频区分；不以反复播放角色说话片段假装实时回应。
4. 缺少可信等待动画时，宁可清楚显示“故事停留在这里，等你回应”，也不编造角色已在自然等待。
5. 现有任务不支持取消时，停止新增任务并追踪已在执行任务的终态和费用；不承诺点击停止立即零费用。
6. 原生会话持续计费而不能经济等待时，需要结束会话并保存语义状态。下一次是重新连接/续接故事，不宣称精确恢复同一视觉现场。
7. 预算上限、已用量和仍可能发生的在途费用由服务端控制；隐藏页面、断网和客户端关闭不替代服务端约束。
8. 任何可能新计费的重新启动，在产品约定的预算授权范围之外必须重新确认。

## 8. 一期验收场景

### 正常体验
- Given 用户只配置了世界、人物和开局，When 点击开始，Then 开场自行生成而不要求先提交一条聊天消息。
- Given 视频已经呈现邀请，When 用户尚未答复，Then 不出现用户已接受邀请的后续事实。
- Given 存在等待事件，When 用户提交与建议不同的自由行动，Then 系统接受该表达或给出可理解的失败原因，不强制点击预设选项。
- Given 用户未收到任何卡片，When 主动提交行动，Then 仍可进入同一处理链路。

### 边界
- Given 用户正在编辑尚未提交的文字，When 到达等待点，Then 草稿保留且不会默认发送或替玩家作答。
- Given 事件已经失效，When 提交旧卡片点击，Then 该操作不重复执行，并提示当前情境已变化。
- Given 同一操作被重复提交，When 系统处理重试，Then 只形成一次逻辑行动；生成请求重试的计费语义另按供应商能力验证。
- Given 人物提出重要决定，When 用户一直沉默，Then 不因等待时长到期自动选择或改变关系。
- Given 计划中的邀请没有出现在实际输出里，When 播放到该片段，Then 对应邀请卡片不作为已发生事件显示。

### 异常与成本
- Given 关键决定候选视频包含玩家未经选择的接受行为，When 进行预播检查，Then 整段不进入用户画面，且待决定事件保持未解决。
- Given 旧方向的视频已经生成但未播放，When 用户提交冲突的新方向，Then 旧视频不再播放，已产生费用仍保留。
- Given 某部署没有可验证的费用上界，When 用户进入生成准备，Then 该部署不开放付费开始入口。
- Given 已结算与在途预留费用接近授权预算，When 新任务最坏费用将使总额超限，Then 服务端不提交新任务。
- Given 素材生成失败，When 用户此前已提交行动，Then 草稿或行动记录保留，且不把失败解释成角色反应。
- Given 等待模式停止新增生成，When 尚有任务在途，Then 界面不显示所有生成均已结束，直到取得相应确认。
- Given 本次预算达到保护边界，When 世界仍等待回应，Then 不自动续费或重启；允许保留当前状态与退出。
- Given 没有低成本连续等待能力，When 视频片段结束而事件未解决，Then 界面如实表现停留而非宣称连续生成。

### 实测记录而非虚构指标
分别记录输入确认耗时、意图进入生成耗时、首个关联视频开始播放耗时、结果是否语义响应、画面连续性以及有效游玩/等待成本。延迟的 p50/p95 和门槛需在真实供应商联调后评估；本稿不指定未经证实的秒级承诺。

## 9. 推进顺序与本轮边界

下一次实现优先做一个“开场 → 事件等待 → 自由回复 → 后续视频响应 → 再次等待”的最小纵向闭环。
先验证供应商协议与一轮实测，再讨论等待表现是否足够自然；动态卡片服从事件/播放契约，不先铺按钮。

后续再拓展：语音、可配置的自主推进节奏、多角色、空间点击、共同游玩、云存档。保持平台通用，不把恋爱游戏的关系数值写成所有玩法的必需字段。

本轮仅记录和评审目标，没有修改运行时代码、创建生成任务或验证真实视频效果。

## 10. 设计复核记录

只读评审指出并已补齐：片段内部越过决定的风险、已生成未播放内容的替换规则、供应商预算准入与在途费用预留。上述要求将增加实现与延迟成本，属于必须实测的产品约束，不是当前已经具备的保障。

复核结果：Archimedes 确认原三项阻塞已在建议设计层面解决。此结论仅针对文档自洽性，不代表运行时实现或真实模型效果通过验收。
