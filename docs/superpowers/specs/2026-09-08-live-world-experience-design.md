# 实时世界：游玩体验分镜与运行时设计

状态：设计评审稿，非已实现能力。2026-09-08。
依据：用户批准先设计完整游玩过程、再决定界面；继承实时视频平台、用户自定义剧本、角色、Web/桌面、舒适浅色的约束。


节奏细化：见 [世界会等你：事件等待与玩家主动权](2026-09-09-world-rhythm-and-agency-design.md)（2026-09-09 目标对齐稿）。其中区分剧情等待、画面播放与生成计费；一期默认建议为事件驱动等待，而非每个视频片段强制回合。

## 1. 本次决策

核心产品不是「视频旁边有对话」，而是「玩家的话与行动能够改变持续发生的现场」。

三种形态比较：
- 聊天主导：文本易做，视频成为附属，排除。
- 纯电影加分支：容易理解，但限制用户自由介入，排除作为平台底层。
- 连续现场 + 自由介入 + 情境触发：采用。承担异步响应、过期互动与生成一致性成本，不靠藏按钮回避。

创作态与游玩态必须分开。创作态定义世界与人物，不预写整部剧情；游玩态只暴露当下必要的信息。首发偏恋爱体验，不将恋爱专属数值写进运行时。

## 2. 三层产品结构

### 创作空间
剧本广场 / 我的剧本 / 角色与素材。世界、角色关系、开场条件、玩家身份在这里配置。图片区分角色参考和场景参考；实际能传几张、如何保持一致由 provider 能力约束，不以上传成功代替生成支持。

### 进入准备
展示本次角色、我的身份、起始情境及音频输入选择。画质与比例折叠；生成成本边界在启动前明确。点击开始后才创建可能计费的会话。声音输入默认关闭，不自动开麦。

### 游玩现场
主层是视频与声音；字幕为辅助；临时互动层只响应当下有效情境；系统菜单承载退出、声音、记录。没有永久角色说明栏，没有右侧聊天时间线。

9:16 是内容构图偏好，不是强制网页比例。桌面竖画面完整置于舞台中，周围空间不填满卡片；横画面独立适配。禁止将横素材裁切后宣称竖屏效果完成。

## 3. 一段完整体验分镜

以下书店情境仅供内部测试，可整体替换为调查、旅行或生活情境；不是平台发布的固定剧本。不是承诺按指定秒数生成。

| 节点 | 玩家看到 / 听到 | 可以做什么 | 临时界面 | 系统条件 |
|---|---|---|---|---|
| A 进入准备 | 自己配置的角色和初始情境 | 检查身份、参考图、音频方式，开始 | 简短准备页 | 校验能力与预算，尚未启动生成 |
| B 首画面 | 正在进入；随后真实首画面与声音 | 取消进入，调整声音 | 等待与失败反馈，不摆剧情选项 | 收到媒体并可播放后才进入 active |
| C 自然发生 | 人物整理书籍，环境声延续 | 观看，随时主动输入 | 无剧情卡片；必要字幕 | 不要求玩家每个片段都回答 |
| D 人物邀请 | 人物询问要不要去窗边 | 自己说话、描述别的行动，或接受邀请 | 仅出现与邀请相关的轻量操作；建议可省略 | 邀请必须与已播放场景对齐，而非提前显示未来情节 |
| E 自由介入 | 玩家输入「先不去，我想问问那本书」 | 修改尚未提交的文字，提交 | 短暂输入层，不形成聊天记录流 | 发出带 ID 的意图；不立即更新人物关系 |
| F 等待影响 | 当前画面继续；表达已收到 | 继续看，必要时追加意图 | 低干扰接收反馈；久等时给明确状态 | 接收确认不等于人物理解或画面生效 |
| G 产生结果 | 人物转向书籍，后续对白回应 | 再介入或自然观看 | 旧邀请撤下；无强制下一步按钮 | 输出关联该输入，实际播放后标记呈现；语义是否遵循另行评估 |
| H 改变方向 | 玩家追加「算了，我们出去走走」 | 等待新方向，查看提交失败原因 | 不并列堆叠旧选项 | 未调度方向可合并；已生成内容不承诺撤销 |
| I 异常 | 视频停顿或连接中断 | 重试连接、退出，保留草稿 | 明确缓冲/断线层 | 不用重复旧动作伪装人物仍在回应 |
| J 离开 | 按需唤出的系统菜单 | 结束并保存状态 | 区分静音、暂停播放、停止生成 | 服务端结束确认单独追踪；断线不推定停止计费 |

测试必须同时包含：人物主动邀请、玩家无邀请时主动介入、玩家拒绝建议、连续改意图。不只测试「点击一个选项成功」。

## 4. 主动表达不是剧情按钮

自由表达与剧情触发是两条通道，不能混为一谈。
- 文字：预留明确的「开始输入」快捷键，初次进入说明；非输入焦点下使用，避免捕获所有键盘输入。具体键位在原型测试后确定，不监听全局键盘偷偷记录文字。
- 指针/触屏：画面边缘的按需呼出区提供等价入口，不能依赖 hover 或记忆快捷键才可用。辅助技术可直接聚焦有语义的入口。
- 语音：用户主动启用后才能使用；录音状态必须可见，一键停麦。语音接通前不显示可用的假麦克风。
- 整张画面点击弹框撤销：它抢占未来物件/人物交互语义，也容易误触。

主动输入时界面只服务这一次表达，不展示用户/助手气泡。输入展开的位置应避开人脸与有效互动区域；若没有可靠构图信息，使用固定舞台外安全区，不臆造人脸坐标。

## 5. 情境交互契约

互动有类型与生命周期，不是 LLM 随意吐出几个按钮。

类型：邀请回应、行动建议、物件操作、必要确认。结构至少包含：
- interactionId、sceneRevision、关联媒体片段 ID；
- trigger（输出开始播放 / 已验证的场景事件）；
- 类型、简短可见文案、语义 action，而非直接执行任意模型代码；
- 有效期与失效条件、是否必须确认、自由输入是否可替代。

生命周期：proposed → eligible → visible → selected / dismissed / expired。
- proposed 不上屏；eligible 要求对应场景已可见。
- 新场景覆盖、对象消失、玩家已采取互斥行动，都使旧互动失效。
- 点击瞬间再检查 sceneRevision，防止点下已过期的选项。
- 不强制倒计时，不自动替玩家作出关系或消费决定。
- 没有可信场景锚点时，只能呈现明确标识的建议，不能声称物件真的可点击。

V1 不做视频内移动热点：生成画面没有天然稳定的对象 ID 和坐标。需模型或视觉追踪提供可靠锚点后再加入。先做语义层的邀请与自由输入，避免假装具备游戏引擎级碰撞/物件系统。

## 6. 产品状态与研发状态对齐

分开维护三种状态，而不是一个 loading：
1. 会话：idle / connecting / active / reconnecting / ending / ended / failed。
2. 意图：draft / submitting / accepted / scheduled / presented / superseded / failed。
3. 媒体：waiting / playing / buffering / stalled。

presented 只意味着与意图关联的输出已经播放，不保证内容百分百服从。不能据此直接修改关系值、背包或事实记忆。事实由经过校验的世界事件提交；模型建议、计划执行与观察到的结果分开存储。

Provider 负责媒体会话与方向传输，不负责 React 布局。LangChain / LangGraph 负责意图理解、人物上下文与结构化互动候选；媒体播放不逐帧经过 agent。这里是职责设计，不是对任何库当前 API 的断言。

服务端保存密钥、预算与会话关闭状态；前端仅使用适合客户端的短期连接凭证。请求幂等、拒绝过期 sceneRevision、重试不重复执行。

## 7. 异步输入原则

- 已收到 ≠ 已进入生成 ≠ 已呈现。
- 新输入是否替换旧输入由语义决定；补充信息可以合并，明确改主意可替换尚未执行的方向。
- provider 不支持取消时，说清楚影响后续画面，不提供假的撤销成功。
- 长时间无响应时提供可恢复反馈，不一直说「正在思考」。
- 会话重建和故事续接不同：能加载记忆不代表能恢复同一视觉世界。

## 8. 原型制作范围

下一轮交付不是单屏改色，而是以下可互相跳转的状态画板：
01 准备 / 02 首画面等待 / 03 自然观看 / 04 情境邀请 / 05 自由介入 / 06 已收到但未呈现 / 07 呈现后旧互动退场 / 08 连续改意图 / 09 缓冲断线 / 10 结束会话。

第一轮重点连通 03—07。媒体尚未接入时采用明确标识的测试情境，并通过演示控制切换事件；不把定时出现的卡片说成对画面的实时理解。测试情境、模拟状态与正式平台内容分开。

暂不新增依赖、不改用户存档、不启动付费生成、不把现有播放器再当设计画板反复覆盖。

## 9. 评审标准

- 观看态有没有逼人操作的控件？
- 没有选项时，玩家能否发现主动参与方式？
- 选项是否与此刻画面相关，而不是相关于未来未播放画面？
- 拒绝建议后能否继续，而非被迫选路？
- 表达成功和画面响应能否辨别？
- 输入是否遮脸，短窗口和键盘导航是否可用？
- 模型失败时有没有保留草稿和明确出口？
- 结束是否真的停止生成，而不是仅离开页面？

下一步设计评审只针对这段体验，不再先争论颜色和圆角。通过后才拆为状态模型、事件契约和对应 UI 的实现任务。
