## 1. 重构的问题，不是再换一种颜色

原方向把“有首页、有角色、有输入、有视频框”当作体验完成。玩家想要的是进入一个可影响的现场，而不是操作视频生成器或管理 AI 对话。

本稿围绕三件事重构：
1. 外部：我的世界与可复用的人物、素材，值得打开、容易开始。
2. 过渡：一句想法形成可确认的开场，不要求用户充当编剧或配置员。
3. 内部：现场先发生；我可以自然介入，相关建议只在情境出现后浮现。

“下一代”是待验证的体验判断，不是功能标签：输入被理解，后果被看到，玩家保有主动权，经历可持续。精美与真实性须同时成立。

### 三个可选方向

- **采用：个人故事空间 + 宽幅参与现场。** 外壳舒适精致，创作与游玩切换清楚；风险是必须真实区分样例与用户经历。
- 对照：杂志式内容橱窗。视觉吸引力强，但容易变成平台提供固定章节，不符合用户驱动。
- 对照：AI 创作画布。便于高级制作，但会让玩家像模型操作员；保留给未来创作工具，不作默认游玩形态。

## 3. 信息结构

主导航为“我的剧本、发现、角色、游玩记录”。默认个人空间，不默认商城／社区。

- 我的剧本：当前用户的草稿和可续接经历；首屏一句话新建，详细管理渐进出现。
- 发现：可改写的提示种子，不是官方剧情、关卡或虚构热榜。
- 角色：基础人格与外观参考可复用；每段故事的关系、经历隔离。
- 游玩记录：确认发生的事实、可恢复状态、确有存储的媒体；三者不混写。
- 素材：在起意、角色、编辑时就近使用；一期不新增独立复杂资源后台。

创建辅助和游玩同一 Story 模型；不为轻量入口再造一套无法迁移的故事数据。

## 4. 可点击画面清单

| 画面／状态 | 主目标 | 此设计稿的行为 | 正式产品补充 |
| --- | --- | --- | --- |
| 个人空间 | 直接起意或回到自己的故事 | 大幅原创视觉样例 + 起意区域；样例明确标注 | 从用户真实故事与有效存档填充 |
| 新用户 | 消除“我需要先写完整剧本”的负担 | 评审栏可切换真实空态构图；无假历史 | 按实际账户数据进入 |
| 起意 | 一句话 + 可选角色／图片 | 原文保留；未填写时有提示 | 可选 AI 整理、服务商数据去向与费用说明 |
| 设定确认 | 确认角色、世界、开场 | 字段可编辑，人物就地选择／编辑，缺角色或开场会提示；附加关系折叠 | AI 推断可辨认，版本与保存状态真实 |
| 发现 | 给用户起点而不是替其编剧情 | 三个可编辑提示种子 | 提示检索与分类；公开投稿后置 |
| 角色 | 让人格不止是选脸 | 名称、性格在页面内存编辑 | CharacterPack 版本、独立草稿与素材用途 |
| 图片 | 明确参考资产与生成的区别 | PNG/JPEG/WebP 本页预览、移除；20MB 本地限制 | 用途区分、远端存储授权、模型输入校验 |
| 自然观看 | 视频主导，无需先发消息 | 切换到宽幅静态构图；没有默认建议 | 预算确认后真实自动开场与播放门禁 |
| 情境邀请 | 有理由地参与 | 仅评审状态触发模拟邀请 | 真实呈现锚点、有效事件、卡片版本 |
| 自由介入 | 不限固定选项 | 按需展开；建议先成为可编辑草稿 | 意图解析、方向调度、取消与幂等 |
| 表达提交 | 不虚报画面改变 | 明示“原型已记录，真实回应尚未接入” | 收件、编排、实际播放、语义兑现分离 |
| 中断 | 诚实恢复，不丢玩家主权 | 评审栏展示断流布局；不是模拟真实收费 | 状态保留、供应商终止、预算再准入 |
| 退出 | 行为后果明确 | 未发草稿提示；确认返回，设定暂留本页 | 停止新增调度，分别追踪费用结束与保存 |
| 游玩记录 | 不编造经历 | 真正空态 | 持久事实、续接授权、可用媒体回放 |

设计稿刷新即清空输入，未使用现有应用 localStorage／IndexedDB，不迁移或覆盖用户数据。角色库在本稿只展示一个设计对象，不代表完成多角色管理。图片用途、预算确认、真实保存恢复尚未做成交互，不计入已完成范围。

## 5. 关键路径与时序

### 玩家路径

```text
我的空间 → 写想法 / 选择自己的设定
→ 确认人物、地点、开局
→ 正式产品：检查素材用途、供应商模型、声音、费用上限
→ 单次明确启动 → 自动开场 → 自然观看
→ 情境已发生 → 邀请出现（也可没有邀请）
→ 自由介入 / 改写建议 / 忽略
→ 系统处理 → 真实画面出现后果 → 下一次参与
→ 结束生成 + 分别保存状态 → 再回来
```

设计稿只验证布局与交互形态；“自动开场、等待真实事件、后果发生”依然是待接通的运行时能力。

### 自由表达

- 稳定入口在舞台外；整张视频点击没有统一绑定打开输入框。
- Enter 可打开表达；不拦截已聚焦的控件和中文输入法。
- Escape 收起并保留草稿；再次打开可继续。
- 点击建议只填入草稿，允许改变话语和行动，不代替用户提交。
- ⌘/Ctrl+Enter 或明确按钮提交；空白不提交。
- 真实运行时需要保存 sceneRevision、cardId、actionId、幂等标识；本设计状态机不是其替代。

### 世界是否等我

不按“每段视频结束”机械进入下一轮，也不永远自动推进。正在进行的、已授权的非关键表演可以完成；承诺、离开、关系改变等关键决定等待明确玩家行动。等待、播放、收费相互独立，详见[世界节奏契约](2026-09-09-world-rhythm-and-agency-design.md)。

## 6. 视觉系统与适配

| 层 | 设计约束 |
| --- | --- |
| 气质 | 明亮、安静、精致，有人与人相处的距离；不做赛博控制台或固定粉色恋爱皮肤 |
| 配色 | 珍珠白 #F6F7F9、白表面、深墨 #252C36、灰蓝 #68717F、强调 #45637E |
| 排版 | 情绪标题少量宋体；操作与阅读无衬线；展示字不用于细小辅助信息 |
| 布局 | 轻量横导航，首页非对称主图＋起意；进入现场后外部导航全部退场 |
| 图像 | 原创成年人物与临海空间为评审视觉；不构成平台固定开场 |
| 表面 | 细边界、18–22px 容器圆角、低阴影；不让圆角卡片淹没内容 |
| 控件 | 深雾蓝主动作、低显著辅助动作、清晰焦点；错误不依赖颜色表达 |
| 动效 | 160–280ms 状态过渡，减少动态偏好下移除；无永久闪烁假忙碌 |
| 宽幅媒体 | 按可用宽高和真实媒体比例 contain；留白胜过裁脸；窗口缩放不更改生成尺寸 |

评审基准 1440×900、1280×720，补充 1024×640 和 1920×1080。小宽度单列只是适配兜底，不是 9:16 优先。表达展开会占用下方空间而非覆盖人物；短窗保留舞台最小高度并可滚动。

## 7. 技术对齐与分层

此次独立 HTML/CSS/JS 是评审载体，不是新技术栈决策，也不意味着生产应用放弃 Next.js。

正式迁移映射：
- `PersonalSpace` / `StorySeedComposer` / `StoryReview` / `CharacterPicker` / `AssetPicker`：应用层视图。
- `WorldStage` / `ParticipationDock` / `ContextCard` / `SessionMenu` / `GenerationBoundary`：现场与生命周期。
- UI 使用 TS、React/Next，与 Tauri 共享；AI SDK UI 适配 LangChain/LangGraph 唯一执行层。
- 动态界面来自受限 schema 和组件注册表，不执行任意模型生成 HTML。
- 视频经独立供应商—模型适配；任务模式与原生实时模式分开；官方 MiniMax 优先，不隐式使用 fal。
- Deep Agents 用于可选离线创作辅助／QA，不让每个玩家回合绕一圈长任务代理。

本稿未接入上述生产服务。`model.mjs` 的小状态机只验证设计交互，不记录世界事实、不包含真实收费、不处理流媒体。

## 8. 验收和实施顺序

1. **本轮评审：** 看整段流程，不只投票颜色。重点判断首页像自己的空间还是模板商店、进入后是否仍像聊天、建议是否抢先出现、表达是否自然。
2. **补齐设计的硬边界：** 素材用途与模型能力、预算授权、真实保存/恢复、长文本／图片失败等，不用静态说明代替最终交互。
3. **技术侧并行验证：** 经预算授权后实测官方模型开场、介入与可见后果，确定实际延迟和可控程度。
4. **迁移生产应用：** 先新壳→设定确认→真实舞台纵向切片，保留数据迁移与回滚，不一次重写所有管理模块。
5. **目标用户观察：** 至少 5 位目标成年人，记录无需指导进入、自由介入和解释后果的能力；是测试目标，不是已有成绩。
6. **二期：** 物体／位置点击应关联媒体帧、场景版本、对象/区域及动作有效性；不得用前端任意热区伪装真实空间理解。

## 9. 资产与已知限制

原创静态场景通过本轮图像生成工具制作，源图与页面所用文件内容相同。没有复制现有游戏角色或官方场景。当前角色靠右的构图用于展示人物、空间和玩家介入区；未来画面不能被 UI 强行锁定为这种构图。

此稿不是 Figma 可编辑文件；可以在浏览器点击评审。没有在聊天中索取／读取模型密钥，没有调用收费视频、语言或语音 API。原图生成属于本轮设计资产制作，独立于未来游戏会话的 API 费用。

验证结果将在本节追加，只记录真实执行的项目，不将离线测试解释为模型可用。

### 本轮验证记录

- 主仓完整测试：12 个文件、103 项通过；其中独立原型状态测试 9 项。角色／开场门禁两项先失败、补齐实现后通过。
- 类型检查与 Next 生产构建通过。此结果证明现有工程检查未受影响，不表示独立原型已集成进 Next。
- 浏览器实际走查：样例→确认→自然观看；模拟邀请→建议填入→修改→Escape 保留→重新打开→提交；自定义原文→缺失引导→编辑人物／性格→填写开场→进入；退出确认；新用户空态；模拟中断与返回观看。
- 1280×720 与 1440×900 实际查看首页、设定／现场主要状态；1024×640 查看长标题与展开输入，测得舞台 983×379、下缘与表达区起点均为 y=427，无横向溢出；1920×1080 展开输入时舞台高度 782，下缘与表达区起点均为 y=840，无横向溢出。媒体均为 contain。
- 基础色对比度计算：正文／背景 13.13:1，次级文字／背景 4.60:1，白字／强调色 6.29:1。不是所有半透明叠层、图片背景或读屏体验的完整无障碍审计。
- 只读同伴复审发现“确认页缺少人物就地编辑”的问题，已补齐入口、性格展示与普通进入校验；复审确认该问题解决。用户审美与体验评审仍待进行。
- 未在本轮浏览器执行文件选择器上传、错误图片解码、全站全部窄屏状态、真实保存恢复和真实 API 验收；不将实现代码存在当作这些流程通过。
