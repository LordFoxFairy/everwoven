# 下一代 AI 产品判断：从生成内容到可持续参与的经历

2026-09-09 初稿；2026-09-10 更新产品判断。产品假设与设计方向，非已实现能力。
长期目标是用户驱动的实时视频游戏平台；一期是完成生成后播放的分段互动。不改变官方供应商直连偏好，不扩大本轮实现。

## 0. 当前产品判断：让 AI 承担制作，让用户保留参与

本节是主会话根据已确认需求作出的产品取舍，不是新增模型实测或用户研究结论。后文早期成熟度审查仅保留作过程记录；发生冲突时，以本节和 FINAL-PRD 的一期边界为准。

### 产品本体

我们提供的是可以参与、改变、延续的经历，不是视频文件，也不是挂着视频的聊天工具。用户的工作是表达意愿、作出行动；平台的工作是组织情境、保持人物与事实、制作下一段表现并管理等待。用户不应成为每一幕的编剧或模型操作员。

三条路线的取舍：视频工作台利于精确控制制作，但把生产负担交给玩家；角色聊天容易上手，但容易让画面退化成附件；可参与的生成式经历最符合目标，但须承担语义兑现、连续性、等待和费用验证。选择第三条，第一期收敛节奏，不以“实时”文案掩盖异步生成。

### 五个连贯的产品空间

1. **回来：继续我在意的经历。** 首页优先呈现用户自己的进行中经历、相关人物和待决定的事情。无记录时给轻创建入口，不编造共同回忆。剧本广场是探索入口，不用推荐瀑布流淹没继续游玩。
2. **开始：描述想经历什么。** 一句意图，可选角色和参考图片，形成可修改的设定草案；确认后开始。复杂世界规则放进进阶编辑。角色模板、剧本设定和每次独立经历分开保存，重开不串记忆。
3. **进入：眼前是现场，不是软件面板。** 桌面默认铺满浏览器内容区的一块媒体舞台；浏览器全屏是独立操作。画面与人物承担主视觉，控制浮在边缘。外部保持明亮、轻盈、清晰；场内颜色由内容决定，不用统一浅色蒙层洗掉画面。
4. **参与：知道可以做什么，也能不按建议来。** 一期观看期间不开放介入；片段结束，在情境需要回应处出现通常 2–4 个不同意图的建议与自由表达入口。显式选项一键提交，编辑是可选动作。建议对应已经看见的事情，不用三种措辞伪装三条路径，也不要求玩家写下一幕的完整结果。人物有自己的动机，不是对一切要求点头的助手。
5. **延续：我的行动留下后果。** 下一段应表现相关回应；只把已确认发生的事情记入当前经历。下次回来恢复待决定的情境。记住事实、人物视觉一致和恢复原画面是三个分别验证的能力。

### AI 感来自分工，而不是装饰

AI 负责补全可编辑设定、提出合乎情境的参与机会、理解自由行动、组织后果与维持连续性。UI 负责可靠呈现这些能力。动态的是交互内容，不是随机变化的操作规则：回应、编辑、收纳、退出的位置和含义稳定；模型只输出受校验的数据，不任意生成可执行界面。

“等待下一步”也需要被设计：观看时不催输入；回应时不倒计时、不自动替玩家选择；提交后保留最后可见画面，准确说明生成中，失败能重试或返回，退出说明在途任务。静帧和氛围动效不冒充实时生成，暂停播放器不代表停止计费。

### 当前最应该做、以及暂时不做的事

当前静态原型只证明布局与操作路径；全屏、悬浮卡片和漂亮图片没有证明 AI 体验成立。下一轮设计交付应覆盖“首次进入”和“再次回来”，而非继续孤立调整播放器按钮。

优先做一段由用户设定出发的两轮完整经历：轻创建 → 自动开场 → 情境建议或自由回应 → 实际相关后果 → 下一处参与机会 → 保存退出 → 返回继续。以同一开局的接受、拒绝、非预设表达检查区别；另检查生成失败、未发送草稿、无历史记录和等待时退出。

评审先回答四件事：新用户是否知道怎么开始和回应；能否指出自己造成的具体变化；返回后是否仍是同一段经历；是否理解等待与费用。没有这些证据，不用页面数量或测试通过数代替产品可用性。

一期暂不扩展多人、交易市场、复杂关系数值或画面物体点击。架构保留行动与媒体帧绑定的边界，二期再验证空间点击；模型适配按供应商实际能力接入，未来实时模式不复用一期的错误承诺。

### 推进责任

产品判断、方案比较、失败状态和自我走查由研发与产品侧先完成，再向用户展示一套连贯体验和明确取舍。用户评审整体是否有参与感，不承担逐个指定按钮、颜色和布局的工作。本次仅更新判断记录，没有修改原型、接通生成或新增验证结果。

## 1. 判断与证据分开

已查阅的一手材料：
- Google Project Genie：创建、探索、重混生成世界的研究原型。https://blog.google/innovation-and-ai/models-and-research/google-deepmind/project-genie/
- Google Genie 产品与限制说明：交互环境生成是研究能力，不应把可探索直接等同于可靠长篇叙事。https://deepmind.google/models/genie/
- Odyssey-1 在 2025-05-28 的研究介绍：基于当前状态、行动和历史预测下一状态，说明行动驱动生成与一次性生成视频的区别，并公开讨论不稳定性。该文章不是本稿对其最新模型或 API 可用性的认定。https://odyssey.ml/introducing-odyssey-1
- Decart API 概览：实时视频处理与异步生成有不同接入场景。实时画面编辑不自动等于开放世界、角色记忆或可验证剧情因果。https://docs.platform.decart.ai/getting-started/overview

本稿推断：模型逐步提供实时画面、动作条件化生成等基础能力，应用价值需要落在持续状态、用户主动权、可理解的交互、体验质量与费用控制。并不据此宣称任一供应商已满足我们的一期完整要求。

## 2. 产品命题

不是“帮我生成一个视频”，而是“让我进入一个世界，我做的事情会被回应，并影响下一次发生的事”。

下一代产品不等于无界面、全语音、处处 agent，也不等于把所有页面交给模型即时生成。应该让用户少管理工具、多直接参与；同时保持稳定入口、可解释的权限及可控成本。

效率产品常希望 AI 多替用户完成步骤；娱乐产品的参与和选择本身就是价值。自动化制作、调度、素材校验，但保留玩家选择、探索与关系形成的过程。

## 3. 四次产品重心迁移

1. 从对话轮次到共同情境：用户说“那个”“刚才那件事”，系统能基于已经呈现的情境理解；不确定时澄清，不猜测画面对象。
2. 从单次生成到连续经历：保存发生的事件、人物关系与当前悬而未决的事情，不只追加聊天历史。
3. 从按钮集合到可发现的行动：自由表达入口稳定，情境卡片动态；二期再让画面指向成为有证据的行动。
4. 从模型效果到结果可信：输入已收、结果已生成、已播放、语义符合是不同指标；漂亮但不回应的画面不是完成。

## 4. 我们应该如何选择形态

- 视频创作工具：价值是成片，用户是导演，需要提示词和重试控制。不是我们的主游玩形态。
- 虚拟角色聊天：价值在对话，易忽略环境与行为后果。可以贡献表达经验，但不作为平台底层。
- 用户驱动的可玩经历：角色、环境和事件共同组成现场；用户说话也能行动，选择留下后果。推荐作为长期形态。

对外可以继续叫剧本广场、角色库、我的游玩。对内应围绕三个对象组织：可复用的世界设定、独立的一次经历、可复用但不串记忆的角色。

从人物关系类体验验证细腻回应，再用调查/探索设定验证通用性；不把测试情境变成固定官方关卡，不一开始追求所有玩法同等成熟。

## 5. 产品体验原则

### 创作简单，能力渐进
一句想体验什么、可选角色或图片即可形成待确认的设定草案。AI 补全世界与开局供用户确认，详细字段保留在进阶编辑中，不要求普通玩家填完管理表单。

### 游玩不工作台化
普通玩家不负责每回合写摄影指令、解释模型参数或手工续接片段。提示词/模型选择属于创作者与设置层。视频是经历的主表现，不是聊天气泡里的附件；一期通过片段结束后的回应驱动下一段。

### 世界有主动性，玩家有决定权
人物按动机行动，在关键选择处等待；一期只在回应阶段开放建议与自由表达，观看和生成阶段不暗示可以实时介入。早期 world-rhythm-and-agency-design 的连续运行讨论属于未来研究。沉默不代表同意，也不是无限计费授权。

### 动态交互有稳定边界
稳定：进入、表达、声音、结束、费用和退出。动态：与已呈现场景绑定的邀请、建议和临时物品信息。模型不任意移动退出入口、生成付款操作或直接执行 UI 代码。

### 记忆是可管理的状态
区分角色模板、当前经历事实、用户个人偏好。不同经历默认隔离；跨经历共享由用户明确选择。提供查看、更正、导出与删除方向。文本状态续接与精确视觉恢复分别标注。

### 舒服来自尊重，而不仅是浅色
不逼迫快速回应，不用离开惩罚、愧疚台词或关系掉分催留。保留未发送内容，明确结束成本。角色表现可以有戏剧性，平台机制不利用情绪压力延长付费时长。

## 6. 研发上值得沉淀的底子

- 世界状态与事件：计划、观察、已确认事实分离；有版本、来源和纠错规则。
- 行动契约：文字/点击/未来语音/空间指向统一描述意图，支持过期、替换与幂等。
- 表现调度：把叙事节拍、媒体生成、播放边界、等待与成本统一协调，而不是每次 API 返回即播放。
- 供应商—模型能力映射：保持协议、价格约束和输入模式真实；未知能力按未验证处理，不以统一函数名假装全部兼容。
- 可重复评测：检验相反指令是否导致相应区别、角色是否持续一致、历史事实是否相容、费用是否越界。

LangChain/LangGraph 是编排实现选择，不是产品卖点。Deep Agents 可研究用于离线创作、检查与整理，不预设其成为每次实时响应的必经层。模型不逐帧调用大型 agent 工作流。

结构化记忆不会自动保证视频一致性；需要闭环评测与纠偏。模型升级也不应无提示改写旧故事，需要版本记录和兼容策略。

## 7. 商业价值假设与防止空泛的平台化

值得验证的差异化是：更自然的互动、更可信的后果、持续的人物与故事、更低的操作负担，而不是可选模型最多。

创作者分享的是可玩的初始设定和规则，不是把别人的私有游玩记忆一起公开。平台增长若形成，来自用户愿意分享和重混自己的创作；社区与交易仍在一期之后。

用户愿意回来的假设：“我想知道我们经历过这些之后，下次会发生什么”。这需要真实连续性，不靠承诺无限记忆或自动生成新章节。

## 8. 下一步验证的四个假设

| 假设 | 如何验证 | 失败后调整 |
| --- | --- | --- |
| 用户感觉自己在参与，而非写提示词 | 观察首次进入后是否能自然行动，记录主动求助/反复打开配置的次数，结合访谈 | 改启动、表达与反馈流程 |
| 自由行动真正影响结果 | 同一初始情境分别输入相反行动，独立多次试验，人工检查视频语义与失败比例 | 调整模型/提示编排/约束，不靠文案宣布成功 |
| 等待舒服且费用可控 | 观察沉默、输入中、改主意与离开场景；统计等待费用、在途费用与响应延迟 | 收敛生成调度与适用节奏 |
| 持续经历值得再进入 | 在知情测试中跨次续接，检查人物、事实、待决定事件与用户意愿 | 先修记忆与续接，不急做更多广场页面 |

把成功行动的比例、输入到可见后果的延迟、世界矛盾率、一次有意义互动的成本和用户主观参与感一起看。不用单一停留时长或生成片段数证明产品价值。测试门槛和样本量待实际技术验证及用户研究计划确定。

## 9. 下一阶段优先级

先证明一个短而完整的可玩过程，然后再拓展创作平台：自动开场 → 人物或情境提供参与机会 → 自由行动 → 可观察的视频结果 → 关键节点等玩家。

本轮只补充产品思考与一手参考，不修改运行时、不启动付费测试，不把未来能力写成已交付。

## 10. 桌面舞台改版后的成熟度复核

本节依据当前代码与上一轮布局验收记录作产品判断，不是新的竞品调研或真实模型实测。结论：方向成立，当前仍是基础原型；尚未证明“用户的行动持续改变眼前世界”。

### 当前已有与尚缺

| 用户价值 | 当前证据 | 成熟度判断 |
| --- | --- | --- |
| 进入现场而非进入聊天 | 桌面宽幅舞台、独立表达区、首画面前不要求输入 | 布局已落地；完整播放中的交互待验收 |
| 输入改变真实视频 | SessionController 区分发送、接收、生成；官方部署尚未有实时适配 | 核心闭环未通过，非接一把密钥即完成 |
| 沉默与改主意受到尊重 | 世界节奏文档已有要求；当前主要是媒体/连接状态 | 待实现事件与播放协调，不能把文档算作能力 |
| 角色记得共同经历 | 有角色模板与本地记录基础 | 尚未证明事实记忆、视觉连续性与跨次续接 |
| 创作轻、游玩自然 | 准备页保留人物与世界；编辑仍以分步表单为主 | 需要简化入口，但不应先于视频因果闭环扩张 |
| 等待和退出安心 | 有显式退出和费用提示 | 服务端预算约束、终止确认与真实费用待验收 |

### 优先问题与具体处理

**P1：基础布局通过不等于实时产品就绪。**
位置：桌面舞台验收与 FINAL-PRD 的核心任务。风险是继续扩大广场/角色管理，却没有用户可体验的真实反馈。处理：下一阶段的交付单位是一段从开始到行动后果的完整体验，不是新增页面数。

**P1：整段预播校验与实时响应存在尚未验证的取舍。**
位置：world-rhythm-and-agency-design 第 6 节。整段检查保护玩家决定权，但会增加等待，与连续流直出不天然兼容。处理：技术验证必须同时报告真实视频响应延迟、检查开销与越过玩家决定的失败案例。测试不通过时，仍判核心体验未通过，不降低标准后称为实时成功。无需关键决定的已授权表现与关键决定候选分开测。

**P1：协议回执不是视频兑现行动的证据。**
位置：SessionController 的 intent 状态与产品的“影响眼前世界”。处理：关联行动、生成候选、实际开始播放的片段；初期由人工复核真实画面是否回应，不宣称自动语义校验已经可用。沉默、拒绝、与建议相反的行动均应进入测试。

**P2：持续记忆和低成本等待仍主要是设计。**
处理：先保存这一轮确认发生的事实和待决定事件；生成计划不直接变成事实。费用以服务端准入与在途任务结算为准；动效、静音、暂停播放均不代表停止生成。

**P2：创建入口仍偏编辑工具。**
处理：保留进阶字段，但后续将默认入口收敛为体验意图、角色/参考图片、可修改的设定摘要。AI 生成摘要须真实接入后再标为智能整理。

### 下一轮只集中证明这一条链路

用户确认自己的设定 → 一键开始 → 自动呈现开场 → 用户自由行动 → 真实视频呈现相关后果 → 在下一处关键决定等待用户。

走查不使用平台固定故事；选择一个由用户配置的关系类情境作内部测试素材。再用另一种自定义情境检查平台通用性，而非马上拓展整套新玩法。

内部验收任务：
1. 同一初始设定，分别输入相反行动，比较实际视频结果，而非只比较回执或提示词。
2. 连续数次介入后，人物、地点与已经发生的事情不因一次新输入被随意重置；记录失败，不承诺绝对一致。
3. 人物发出邀请后，沉默不被解释为接受；未提交的草稿不作为行动。
4. 用户改主意时，明确哪些内容已呈现、哪些候选失效、何时影响后续；不假装取消了已发生费用。
5. 退出后检查服务端终止证据与费用，而非仅检查页面关闭。

## 11. 深度参与感：让玩家成为情境中的人

本节为待验证的体验设计，不表示新增能力已实现，也不将参与感等同于停留时长。

### 核心命题

玩家能够理解自己身处何种情境、知道可以主动做什么、观察到自己的行动如何被回应，并在后续感到这次参与仍然有意义。观看的临场感、行动的因果感和跨时刻的连续性缺一不可。

### 六层参与感及其实现边界

1. **身份与处境。** 开场让玩家从人物称呼、关系、眼前事件中理解“我是谁、为何在这里、此刻有什么值得参与”，而非长篇世界说明。玩家身份来自已确认设定，不由模型暗中改写；不替玩家决定内心感受。
2. **被感知。** 角色回应本次表达中真正重要的部分，并通过语气、动作和环境表现出来。界面确认收到、模型理解意图和视频可见反应是不同事件；未生成的目光或动作不以预录素材冒充本次真实回应。
3. **选择有差别。** 接受、拒绝、绕开建议或主动提出新事，应该得到语义上有区别的后果。自由并非任何事情必然成功：人物可以有动机和边界，但回应应当与情境相符，技术失败另行说明。
4. **共同创造而非独自编剧。** 人物与世界提供可参与的事情，玩家无需每次写出完整下一幕。主动性受已确认设定约束，不用事故、追问或关系惩罚强迫玩家回应。
5. **后果可延续。** 已经发生的承诺、拒绝、共同经历与未完成的事情成为后续依据。生成计划不等于事实，记忆不直接保证画面一致；跨次续接须独立验收。
6. **节奏与掌控。** 观看、思考、表达都应成立。一期把可游玩片段的结尾组织成参与节点，播放结束后等待玩家，不把任意一句对白切成一个任务，也不无限自动续生成。短时间沉默不是同意、失败或新的付费授权。

### 一段内部体验测试，不是平台预置关卡

用户自定义了人物、地点及开局。角色提出一项邀请后，玩家不接受预设方向，而是说“先等等，我更想知道你刚才为什么犹豫”。

检查链路：
- 已呈現的犹豫若没有足够证据，系统不伪造确定的过去；表达含糊时自然澄清。
- 行动进入处理后，仅给轻量、准确的接收状态，不先用文字宣布人物已经改变行为。
- 真实输出应回应玩家关注的事情，不能忽略表达继续原定邀请结果。
- 角色回应可以保留自己的动机，玩家的自由不等于对角色结果的绝对控制。
- 后续遇到相关情境，已确认发生的对话或行为可以被合理引用，而不是机械复述全部记录。
- 玩家不继续追问时，角色不能替玩家认定关系升级、答应邀请或完成亲密行动。

参与感来自这个因果链条，而非出现一个好感度加分动画。

### 界面的角色

- 桌面宽幅视频是铺满内容区的主舞台，回应界面悬浮并可收纳，避免主要人物区域；默认没有聊天记录墙。
- 回应阶段的自由表达入口始终可发现，观看与生成阶段不开放输入，不要求每次操作都打开大表单。
- 一期通过自然语言支持说话与行动，不要求玩家先选复杂的命令模式。存在多种显著不同解释时才澄清。
- 修改世界设定属于创作意图，与角色内行动分开确认，避免一句话意外覆盖经历。
- 情境建议仅在相应事件已呈现且仍有效时出现；正常回应节点提供 2–4 个有区别的建议。缺少可靠建议是应处理的降级状态，不以空白输入框作为正常设计。
- 稳定保留声音、表达、结束与费用入口；动态生成不意味着控件随机移动。
- 镜头、声音和人物调度作为叙事表现参与设计，但能否在当前视频模型中受控需要实测。构图建议不作为能力承诺。
- 二期物体点击增加指向精度，而不是参与感的前置条件；必须绑定可见帧、对象和媒体实际显示矩形。

### 一期收敛

先证明文字驱动的一段持续经历，包含自动开场、非预设行动、真实回应、一次可回忆的后果与一次受尊重的关键等待。优先深度而非玩法数量，不先增加关系数值、签到、排行榜、多人与大量角色页面。

### 如何知道不是自我感动

知情走查同时观察与访谈：
- 用户是否能说清自己是谁、眼前发生什么，以及自己想尝试的行动？
- 相反行动在同一初始情境的独立试验中，是否产生相应而非随机的差异？
- 用户能否具体指出“这一刻因为我做了什么而发生变化”？
- 用户是否需要不断重述身份、地点和前一刻发生的事？
- 用户沉默、输入中、改主意时，是否感到被催促、被代替选择或不清楚费用？
- 用户返回是因为愿意继续这段经历，还是因为退出惩罚或愧疚设计？后者不是成功信号。

测量画面响应时延、语义响应结果、连续性错误和每次有效互动成本，并记录用户对等待的主观感受。当前不设虚构的满意度、响应成功率或秒级承诺。
