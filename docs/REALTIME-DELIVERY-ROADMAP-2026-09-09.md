# 实时交互游戏平台：收敛后的推进顺序

日期：2026-09-09。不是预录互动影片。ALIBI 借鉴的是场景行动体验。

## 当前代码与目标之间的差距

已存在 H3 Director 传输适配器及本地开发代理，但未完成真实收费联调；现有先进入静态 Player、再打开菜单连接模型的路径仍不符合一键开始的产品定义。现有 card/运行时联动尚未实现。文档、mock 测试或 UI 提交成功都不等于真实游戏闭环完成。

## 一期执行顺序

1. 合并启动路径：剧本详情/继续游玩直接进入统一准备与会话启动；撤销正式游玩中的静态中间层。首次确认预算与输入方式后再开始，后续不要求玩家自己找 provider。无密钥留在准备页。
2. 做真实会话技术验证：开始后自动生成开场；测首帧、文本介入、至少三次方向改变、错误与停止；记录真实结果，不只测试 mock。真实调用前另行确认测试费用上限。
3. 扩充运行时：世界状态、统一意图、场景版本、生成与呈现的不同状态；保留供应商 chunk 元数据。解决媒体时间映射后再让场景卡片出现。
4. 连接叙事编排：基于用户剧本生成当前情境与互动候选，并通过已呈现证据校验。无输入时不是强制剧情快进；不能可靠等待则显式设计节奏边界。
5. 用三种不同类型的自定义剧本验收通用性，例如人物关系、调查和探索；这些只是内部测试，不变成固定售卖内容。

## 二期执行顺序

A. 点击位置 + 点击时帧证据 → 目标识别 → 语义行动 → 实时视频结果。
B. 同一镜头的少量关键物体跟踪与按需高亮。
C. 遮挡/镜头切换后的身份恢复、跨设备空间交互。

二期不阻塞一期上线，亦不在一期放置假的可点击物件。契约现在设计，视觉模型部署与热点 UI 到二期实现。
