# 实时视频交互原型：参考研究与下一版设计依据

日期：2026-09-08。范围：用户提示驱动的视频游戏平台，而非聊天皮肤、固定分支电影或视频编辑器。

## 证据边界

本轮核对官方页面、公开产品入口以及 UNREEL 播放器和流状态机源码；未付费开启外部模型会话，未测量端到端响应，也未完成这些产品的全流程试玩。官方性能描述不是我们的实测结果。以下设计建议是推导，不是竞品已有功能的宣称。

## 2. 源码带来的实际提醒

UNREEL 播放器将当前 video 与下一段预载 video 分开；控件在约 3.2 秒无鼠标动作后淡出。它处理浏览器阻止有声自动播放的情况。缺下一段时先停留尾帧，超过 4 秒可能重播旧片段。我们的设计可以参考预载与声音恢复，但重播旧动作会让玩家误以为人物没有理解，必须有明确缓冲状态，不能无标识假装新内容。

其流状态机有 starting / playing / buffering / error，渲染缓存上限为 3 段。预生成越多并不天然越好：自由输入到来时，旧方向生成的未来内容可能已过时。我们的缓存策略应按可接受响应时间确定，尚未播放的旧方向内容需要失效规则。客户端停止消费也不等于服务端生成与计费已结束；必须单独验证关闭契约。

Biome 仓库为 GPL-3.0。仅参考交互和架构，复用代码前单独评估许可义务。其 README 与安装页面对 GPU 门槛描述存在差异，暂不做统一硬件承诺。

## 3. 下一版形态：创作空间与游玩现场分开

### 进入前：准备，而非后台配置表
- 剧本广场、我的剧本、角色库留在浅色平台外壳。
- 剧本定义世界规则、人物关系与开场条件，不预写后续情节。
- 进入前只展示角色、起始情境、画面比例、声音和本次费用边界。
- 上传图片必须标用途：角色参考、场景参考、开场参考；由 provider 能力决定是否可用于生成。上传成功不代表模型支持多角色一致性。
- 没有自定义角色素材时显示明确占位，不擅用另一角色肖像。
- 高级模型参数折叠；会话固定参数说明「下一次进入生效」。

### 游玩中：视频现场，而非聊天窗口
- Web 与桌面优先，不将 9:16 内容误解为整个应用只能做手机布局。
- 宽屏的竖屏视频保持比例，旁侧留轻量互动区；横屏视频采用更宽舞台。不要裁掉人物来填满容器。
- 默认没有聊天记录列。字幕贴近画面底部安全区，输入与卡片不遮角色脸和关键动作。
- 表达入口短而轻；聚焦后才展开输入，语音仅在真实能力接通后启用。
- 动态卡片绑定当前场景与状态，可为行动、物件、追问或确认，不固定 ABCD，也不必每轮出现。
- 表达灵感不能只写「描述想去的地方」这类操作说明；建议必须具体、可执行，同时不剥夺自由输入。
- 历史、角色详情、设置按需打开；核心舞台持续可见。
- 外壳明亮柔和，视频内控件根据实际画面保证对比度，不用全屏白色滤镜制造浅色风格。

### 输入与结果：三个阶段必须真实
1. 正在提交：保留输入，失败可重试。
2. 已接收：表示服务端确认，不表示画面已变。
3. 已影响画面：只有输出与该输入关联且已播放才显示完成。

连续输入需说明合并或替换规则；撤回只能作用于 provider 尚可取消的阶段。过期卡片自动收起，避免对旧场景继续下指令。语音识别结束不等于角色响应。

### 离开与异常
- 静音、暂停本地播放、停止生成是不同动作；持续生成的成本不能被播放暂停掩盖。
- 网络断开时显示重连状态并保留草稿；重建会话是否恢复世界一致性需实测。
- 会话达到供应商时限前提示，跨会话续接不能假装天然连续。
- 退出确认应说明生成是否结束；保存剧本状态与保存视频不是同一能力。

## 4. 底层契约建议（待实现，不是现状）

VideoProvider 不止 submit(text)：需要 capabilities、openSession、sendDirection、events、closeSession；取消与恢复为可选能力。事件用 sessionId / inputId / segmentId 对齐接收、输出和播放。模型未提供关联时不得伪造「已生效」。

LangChain / LangGraph 管人物记忆、世界状态、输入理解与结构化互动建议；媒体传输与播放在独立会话层。不是每个片段或视频帧都要经过 agent。DeepAgents 是否加入取决于创作工具任务，不是播放实时性的前提。

前端用统一状态驱动：准备 → 连接 → 首画面 → 游玩 → 方向待生效 → 游玩；异常分支为缓冲、重连、失败、结束。原型可以演示这些状态，但必须标明模拟，不用本地文件播放冒充生成。

## 5. 下一轮原型清单与验收

P0：先完成一条可信闭环，而非继续加装饰。
1. 准备页：角色/参考图/起始条件/会话成本。
2. 游玩页：宽屏竖画面与宽屏横画面两种布局，短窗口也不遮脸。
3. 一次输入：提交、确认、延后影响画面的完整状态。
4. 一次异常：缓冲或断线，保留输入与可恢复操作。
5. 退出：结束生成与保存状态的清晰反馈。

P1：语音权限与打断、场景动态卡片、自定义图片能力适配、记忆抽屉。
P2：多人共同驱动、创作者发布与版本、片段分享、跨模型续接。

测试任务：用户进入自定义剧本 → 表达「我们去窗边聊」→ 区分请求已收到与人物真正开始行动 → 连续追加一句 → 调整声音 → 退出。观察是否仍需解释界面、是否误认为静态素材是真实生成。

应记录首画面耗时、输入到确认、输入到实际画面变化、卡顿、角色一致性和每分钟成本。先测实际分布，再承诺响应 SLA。

## 6. 尚待验证

- 对公开可试玩案例进行实际视觉与交互走查；入口文字不等于已体验。
- 真实 API 的首画面/方向延迟、声音可控性、关闭计费和连续输入行为。
- 恋爱向中文语音、长对话人物稳定性，以及自定义肖像的支持范围。
- A2UI / AG-UI / 自定义结构化卡片的取舍应在卡片生命周期稳定后决定，不先用协议名称替代设计。
