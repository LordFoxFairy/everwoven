## 已设计状态
1. 持续视频现场：视频是主区域；自由输入始终可用。
2. 收到输入：当前视频继续，等待后续生成，不误称画面已经改变。
3. 后续画面呈现：以角色起身为测试案例，仅说明交互因果，不成为平台内置固定剧情。
4. 未提交时改口：替换/撤回待发指令，保留原始输入历史。
5. 已提交时改口：不能假设立即撤销；旧内容可能短暂出现，新指令影响后续可调整的生成。
6. 缓冲/断线：明确标注最后画面不是直播，保留输入，不盲目重复发出行动。

## 设计语义
- 用户输入回执、Provider接收、对应视频开始播放、语义执行正确，是四种不同证据。
- 已播放内容不回滚。撤回只对实际可取消的待发指令开放。
- 场景、角色、用户上传参考图是初始生成条件，不是产品主体。
- 不以独立视频下载卡片替代持续视频现场。
- 不把网络等待伪装成角色犹豫或情绪。
- 没有实测就不展示秒级生效倒计时或声称零延迟。

### 本阶段交付边界

- 交付是可点击的中保真 Figma 交互原型，不是实时视频产品或高保真角色视觉成品。
- 所有背景/人物均为明确标注的矢量占位；没有实际播放视频，没有语音采集，也没有访问麦克风。
- 自由文本及语音转写是固定样例。草稿保留是设计约定，当前演示不验证任意文本编辑与持久化。
- 卡片是场景生成 UI 的示例状态，不是固定剧情、强制选择题，也未接入 AG-UI/A2UI 协议或真实动态 schema。
- 回执只演示指令接收状态，不代表模型已经响应、角色实际执行或视频生成成功。
- 1800ms仅是原型回执停留时间，不是API速度承诺。
- 顶部会话菜单/退出等非本Goal主流程入口仍是视觉占位；正式产品的计费、停止远端生成、上传引用和异常恢复另行实现。
- 本Goal未修改前端代码；localhost仍是早期版本，应通过上述Figma演示入口查看本交付。
